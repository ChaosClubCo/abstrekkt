MCP is the single biggest unlock in Claude Desktop, and the setup takes fifteen minutes once you've done it once. Here's the shortest honest path from zero to a working custom server.

What you actually need

  • Claude Desktop installed and signed in
  • Node.js 18+ or Python 3.10+ (whichever your server's written in)
  • A text editor that doesn't fight you on JSON

That's it. No accounts, no tokens, no cloud infra. MCP servers run locally; Claude Desktop talks to them over stdio.

The four-file shape of a minimal server

Every MCP server is the same four things:

  • package.json or pyproject.toml — declares the entry point
  • A server object that registers tools, resources, or both
  • Handler functions that do the actual work
  • An entry in claude_desktop_config.json telling Claude how to launch it

If you're starting from one of Anthropic's templates, the first three are done. You're really writing two things: what tools exist, and what they do.

Where people get stuck

The config file. On macOS it's ~/Library/Application Support/Claude/claude_desktop_config.json. On Windows it's %APPDATA%\Claude\claude_desktop_config.json. If it doesn't exist, create it. Claude has to be fully quit and relaunched after edits.

Absolute paths. Use absolute paths in the command and args. Tilde expansion doesn't work. Relative paths silently fail.

Tool descriptions. The model decides when to call your tools based on their names and descriptions. Vague names don't trigger. Treat the description field like a marketing headline for the model.

The smallest useful server

Pick one annoying thing you do in a browser tab three times a week. A Notion query. A Linear filter. A repo search. Wrap that one thing as a tool. Ship it. Iterate.

Three narrow servers beat one big one every time. You'll learn faster, the model will route better, and each one can be killed without breaking the others.
