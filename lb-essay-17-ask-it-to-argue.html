Ask It to Argue

Most people ask AI for help. The ones getting something real out of it ask for a fight — and then have to already know enough to judge whether the fight was real.

Most people ask AI for help. The ones getting something real out of it ask for a fight.

A model is built to be useful, and useful gets trained into something close to agreeable. Hand it a plan, even a bad one, and it will find the best version of that plan and execute it cleanly. The input was garbage. The output is polished garbage — which is worse than obvious garbage, because polished is harder to catch.

Ask it a different way and the same tool changes shape entirely: "Here's my plan. Find ten ways it fails. Simulate how a competitor responds to it. Show me the gap in the logic I'm not seeing." Same model. Completely different job.

The Catch Inside the Catch

That's adversarial reasoning, and it's the actual difference between using AI as a word processor and using it as a pressure-tester. But there's a second layer under it that doesn't get talked about enough: you have to already know enough to judge whether the pushback is real.

The model tells you your plan has a flaw. Is it right? You have to be able to answer that yourself. If you can't, you haven't gotten friction — you've gotten a second, fancier-sounding form of agreement, because you were going to accept whatever it said either way.

Ask it for help and it agrees with you faster. Ask it to argue and it finds the argument — but checking whether the argument holds is still your job.

The Part That Doesn't Make the Demo

Pressure-testing a plan against a model willing to attack it is a real capability. It's also one that requires the same judgment it's supposedly replacing, applied one level up — not to the plan anymore, but to the critique of the plan. The model got better at finding holes. It didn't get better at knowing which holes matter.

That's still the seat I sit in.
