[BASE44 PROMPT] Instrumentation & Analytics
============================================
Atomic, self-contained. Paste into app.base44.

You are designing the INSTRUMENTATION layer for a deal-sourcing / portfolio app.
Goal: a consistent event taxonomy + KPI capture so every other layer is measurable
and the A/B test (Outcome-First vs Standard) can be evaluated.

Generate logic that:
1. Defines the canonical event taxonomy used across all 8 layers:
   onboarding_started, step_completed, activation_reached, habit_trigger_sent,
   reward_shown, value_moment_detected, expansion_accepted, lifecycle_stage_changed,
   integration_connected, sync_failed, ... (extend as needed).
2. Specifies required properties per event (userId, ts, stage, variant) and forbids
   logging raw financial figures (hash/bucket instead).
3. Maps events to the KPIs in /dashboards/kpi-definitions.md (activation rate,
   time-to-activation, D7/D30 retention, expansion rate, churn).
4. Tags each event with the A/B variant for experiment analysis.

Requirements:
- Emit a single, validated event envelope; reject malformed events.
- Provide an analytics view spec for each KPI.
- Privacy: no PII or raw deal/portfolio values in event payloads.

--- IMPLEMENTATION NOTES ---
- This taxonomy is the contract every other prompt emits against — define it first.
- Variant tagging is what makes outcome-first-vs-standard.md measurable.
