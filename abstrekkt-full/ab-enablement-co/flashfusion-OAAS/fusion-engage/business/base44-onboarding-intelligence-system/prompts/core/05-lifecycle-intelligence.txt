[BASE44 PROMPT] Lifecycle Intelligence
=======================================
Atomic, self-contained. Paste into app.base44.

You are designing the LIFECYCLE ENGINE for a deal-sourcing / portfolio app. Goal:
classify each user into a lifecycle stage and emit the next-best-action that every
other layer (activation, retention, expansion) reads from.

Stages: new -> onboarding -> activated -> habitual -> power_user -> at_risk ->
dormant -> reactivated -> churned.

Generate logic that:
1. Computes the current stage from onboarding_state + behavioral signals
   (activationReached, session cadence, decay flags, expansion events).
2. Writes lifecycle_state {stage, enteredAt, nextBestAction, confidence}.
3. Defines transition rules + the trigger thresholds between stages.
4. Emits next-best-action per stage (e.g. at_risk -> win-back referencing outcome).
5. Prevents cross-layer message collisions (one primary action per user per window).

Requirements:
- Emit events: lifecycle_stage_changed{from,to}, next_best_action_set{action}.
- lifecycle_state is the single source of truth other prompts consume.
- Make thresholds configurable, not hard-coded magic numbers.

--- IMPLEMENTATION NOTES ---
- This is the orchestration brain; build the schema (lifecycle-state.schema.json) first.
- at_risk detection should consume retention_decay_detected from the habit-loop layer.
