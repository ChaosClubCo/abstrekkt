[BASE44 PROMPT] Power-User Expansion & Monetization
====================================================
Atomic, self-contained. Paste into app.base44.

You are designing the EXPANSION layer for a deal-sourcing / portfolio app. Goal:
grow value (and revenue) for engaged users by surfacing upgrades at genuine value
moments — never before activation.

Hard gate: only run when onboarding_state.activationReached == true AND the user
has hit a usage signal (e.g. saved filters, deals tracked, sessions/week).

Generate logic that:
1. Detects value moments (hit free-tier limit, repeated high-intent action).
2. Offers the contextually-relevant upgrade (more deal alerts, advanced analytics,
   team seats, syndicate tools) with a clear before/after value statement.
3. Supports expansion paths: tier upgrade, add-on, seat expansion.
4. Respects a cool-down so offers never feel like nagging.

Requirements:
- Emit events: value_moment_detected, expansion_offer_shown{type}, expansion_accepted,
  expansion_dismissed.
- Read lifecycle_state to target only users in an expansion-ready stage.
- Tie each offer to a measurable ROI claim for the user.

--- IMPLEMENTATION NOTES ---
- Premature upsell is the #1 churn risk here; the activation gate is non-negotiable.
- Monetization triggers must reference real usage, not time-on-platform alone.
