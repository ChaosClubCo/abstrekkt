## What this project actually is

ProjectX is a **React 19 + TypeScript SaaS platform skeleton**. Each feature is a
self-contained "module" directory at the repo root (e.g. `auth_module/`,
`multi_tenancy/`) holding its own `src/`, `package.json`, and tests. ~30 of the
~50 advertised modules currently have real `src/` code; the rest are docs/stubs
(see `docs/MODULE_STATUS.md`).

> files over them.** `README.md` and `docs/ARCHITECTURE.md` describe React 18 /
> Vite 5 / Tailwind 3 and a populated `packages/shared` workspace. None of that
> matches the installed reality below. `docs/CLAUDE.md` is unrelated — it is
> auto-generated by `/sync-agent-context` and documents the *vendored reference
> repos* (awesome-copilot, spec-kit, SuperClaude…), not this app.

## Commands

```bash
npm install            # Node >= 20, npm >= 10 required
npm run dev            # Vite dev server on http://localhost:5173 (proxies /api -> :3001)
npm run build          # tsc (full typecheck) then vite build -> dist/
npm run typecheck      # tsc --noEmit, no build
npm run lint           # ESLint 9 flat config (eslint.config.js)
npm run lint:strict    # same, --max-warnings 0 (use this to gate)
npm run lint:fix
npm run format         # Prettier across ts/tsx/js/jsx/json/md
npm test               # Vitest (watch)
npm run test:coverage  # Vitest run + v8 coverage; enforces 80% global thresholds
```

Run a **single module's** tests by passing a path/name substring to Vitest
(there is no `--scope` flag despite what the README says):

```bash
npm test -- auth_module                       # all tests under auth_module/
npm test -- auth_module/src/__tests__/x.test.ts   # one file
npm test -- -t "signs the user in"            # by test name
```

## Architecture

### Module-per-feature layout
Each module mirrors the same structure and is an npm package named
`@projectx/<name-with-hyphens>` (note: **directory uses `snake_case`, the package
name uses `kebab-case`** — `auth_module/` → `@projectx/auth-module`):

```
<module>/
  package.json
  README.md
  src/
    index.ts        # barrel exports
    components/      # PascalCase.tsx, default-exported React.FC
    hooks/           # useXxx, named exports
    api/             # axios calls against /api/<module>
    types/           # interfaces (entities) + type aliases (unions)
    __tests__/       # *.test.ts(x)
```

### State management contract
- **Server state → TanStack React Query.** Module hooks own queries/mutations and
  invalidate by query key. Key convention: `['module_name']` (list),
  `['module_name', id]` (item), `['module_name', 'search', q]`.
- **Client/UI state → Zustand** (with `persist` middleware for preferences).
- **URL state → React Router 7.**
- Cross-module coordination is done by **invalidating shared React Query keys**,
  not by direct cross-module calls.

The standard module hook returns `{ items, isLoading, error, create, update,
remove, isCreating }` backed by `useQuery` + three `useMutation`s. Match this
shape when adding modules — see `docs/CONVENTIONS.md` for the full pattern.

### Build & tooling reality (verify against config files, not the docs)
- **Vite 6** (`vite.config.ts`) — manual vendor/query chunks, sourcemaps, `/api`
  proxy to `localhost:3001`. The app entry is `index.html` → `/src/main.tsx`.
- **Tailwind v4** via the `@tailwindcss/vite` plugin — **there is no
  `tailwind.config.js`**; do not add content globs by hand (v4 auto-detects).
  Ignore any doc step that says to edit `tailwind.config.js`.
- **TypeScript 5** in strict bundler mode, `noUnusedLocals`/`noUnusedParameters`
  on, `noEmit` (Vite emits). Path aliases: `@/*` → `src/*`,
  `@projectx/shared` → `packages/shared/src`.
- **Vitest 3** (`vitest.config.ts`): jsdom, `forks` pool, globals on,
  `vitest.setup.ts` preloaded, and an **explicit hardcoded `include` list of
  module globs** — a new module's tests won't run until you add its glob there
  (and add its `src` to `tsconfig.json` `include` for typechecking).

### Important structural gaps to know before you act
- **`src/`, `packages/`, and `modules/` are empty.** `index.html` points at
  `/src/main.tsx`, so `npm run dev` has no app shell / route composition yet —
  modules currently exist as isolated packages, not a running app.
- Consequently `@projectx/shared` (the `packages/shared/src` alias) **does not
  resolve** — the "import from `@projectx/shared`" examples in the docs are
  aspirational. Modules are self-contained today.
- The npm `workspaces` globs (`packages/*`, `modules/*`) point at the empty dirs,
  not at the real top-level module folders.

## Conventions (enforced by lint/TS, summarized from docs/CONVENTIONS.md)
- Components: `PascalCase.tsx`, typed as `React.FC`, default-exported.
- Hooks/utils: named exports; hooks prefixed `use`.
- Barrel `index.ts` per directory; import order external → `@projectx/*` →
  relative → type-only.
- Exported functions get explicit return types; prefer optional chaining /
  nullish coalescing; extract logic into hooks to keep components thin.
