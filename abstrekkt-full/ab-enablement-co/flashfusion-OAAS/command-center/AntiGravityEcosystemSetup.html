Top 5 GEMINI.md Best Practices

The GEMINI.md file is the brain of your workspace. These five practices maximize agent effectiveness, balancing context window usage with output precision.

Best Practice Impact Analysis

Comparison of impact on key developer metrics.

1. Context Pruning & Pinning

Efficiency

Description: Explicitly define which files are "Pinned" (always read) vs. "Pruned" (ignored) to save tokens.

# RULE: CONTEXT_OPTIMIZATION
- IF task_type == 'frontend_ui':
  PIN: ['/src/components/Button.tsx', '/tailwind.config.js']
  IGNORE: ['/backend/**', '*.test.ts']
- ALWAYS summarize file content > 500 lines before editing.

2. Atomic Thinking Protocol

Stability

Description: Force the agent to break complex tasks into single-responsibility steps before execution.

# RULE: ATOMIC_STEPS
1. PROPOSE a step-by-step plan.
2. WAIT for user confirmation.
3. EXECUTE one step at a time.
4. VERIFY outcome before proceeding.
--- DO NOT batch edits across disparate modules.

3. Test-Driven Generation

Quality

Description: Mandate that the agent writes the test case *before* the implementation code.

# RULE: TDD_STRICT
- Create `*.spec.ts` demonstrating the bug or feature.
- Run test -> MUST FAIL.
- Write implementation.
- Run test -> MUST PASS.
- Only then commit.
