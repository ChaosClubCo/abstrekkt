# Semantic Memory Hierarchy

## Purpose

The hierarchy prevents all knowledge from living at the same cognitive level.

## Levels

### Level 0 — Source Artifacts

Files, images, videos, apps, prompts, docs, notes.

### Level 1 — Extracted Facts

Named entities, dates, owners, decisions, systems, relationships.

### Level 2 — Operational Records

Projects, workflows, tasks, agents, migrations, assets.

### Level 3 — Patterns

Reusable prompts, playbooks, design systems, governance policies.

### Level 4 — Strategic Doctrine

Constitution, architecture philosophy, operating principles.

### Level 5 — Executive Memory

Current priorities, risks, next decisions, active bottlenecks.

## Memory Promotion Rules

A piece of knowledge may be promoted when:

- it recurs at least three times
- it controls system behavior
- it affects multiple projects
- it prevents future errors
- it becomes part of client delivery
- it informs agent routing

## Memory Aging Rules

Memory must be reviewed when:

- source changes
- confidence drops
- entity is stale
- relationship conflicts appear
- a newer source supersedes it
- usage frequency falls below threshold
