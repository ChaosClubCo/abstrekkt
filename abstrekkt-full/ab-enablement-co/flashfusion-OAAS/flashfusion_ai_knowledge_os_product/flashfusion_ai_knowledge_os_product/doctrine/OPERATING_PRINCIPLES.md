# Operating Principles

## 1. Design For Entropy

Every system drifts. Every schema changes. Every prompt decays. Every agent may overreach. Every memory store becomes stale without active governance.

## 2. Prefer Explicit Failure

A visible unresolved relationship is safer than a guessed relationship.

## 3. Compress Before Expanding

When complexity grows, define primitives and abstractions before adding more features.

## 4. Treat AI As Probabilistic Infrastructure

AI outputs require confidence, provenance, review states, and mutation policies.

## 5. Make Relationships Navigable

If A references B, B must show A where relevant. Relationship context must be bidirectional unless intentionally scoped.

## 6. Build For Replay

Migrations, decisions, transformations, and agent actions must be replayable or reconstructable.

## 7. Preserve Human Context

The system should help humans remember, decide, and act without becoming the bottleneck.

## 8. Separate Raw Knowledge From Operational Memory

Stored notes are not operational memory until they are classified, related, governed, and made actionable.
