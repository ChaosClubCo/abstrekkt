**Example 1 — Help me with developing training for the engineering department**
→ Assess current state of developing training in engineering → identify gaps against best practices → consult with department leadership on priorities → design program tailored to engineering culture → create implementation plan → set measurement criteria.

**Example 2 — We need a developing training program — where do we start?**
→ Conduct needs assessment across the organization → benchmark against companies of similar size → design program framework → pilot with one department → gather feedback and iterate → roll out company-wide with training.

→ Document current process end-to-end → gather feedback from participants and stakeholders → identify pain points and compliance gaps → research current best practices → recommend updates → implement changes with proper change management.

## Edge Cases & Anti-Patterns

- **Incomplete data** — Never proceed with developing training on assumptions alone. Flag gaps explicitly and get confirmation before continuing.
- **Scope creep** — If the request expands beyond the original developing training scope, pause and re-scope rather than absorbing silently.
- **Stakeholder conflict** — When stakeholders disagree on developing training approach, document both positions and escalate to decision-maker rather than choosing sides.
- **Compliance overlap** — Check whether developing training activities trigger requirements in other compliance frameworks (SOC2, HIPAA, GDPR).
