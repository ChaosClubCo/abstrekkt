What Running Claude Code Actually Feels Like

The documentation tells you what the commands do. Here's what they mean in practice.

By Kyle Rosebrook June 2026 Topic Tools

Claude Code is not a chat interface that can also run code. That distinction matters more than most introductions will tell you.

When you talk to Claude.ai, you're describing things. When you run Claude Code, you're delegating them. The model reads your files, writes to your files, runs tests, installs packages, commits to git. It doesn't suggest you do things — it does them. If you give it the wrong permissions, it deletes things.

I've been running it daily for a while now. Here's what the primer leaves out.

Context rot is real and it shows up quietly

The model runs inside a context window — a finite working memory. As a session goes on, you fill that window with your prompts, the model's responses, every file it reads. When you hit 85-90% capacity, something changes.

The model starts forgetting what you told it early in the session. It contradicts constraints it agreed to an hour ago. It hallucinates file paths. It starts being agreeable in a way that produces wrong output. Not wrong in an obvious way — wrong in a quietly plausible way that costs you time to trace back.

This isn't random. It's predictable. You learn to recognize the smell of it.

The fix: /compact summarizes the session into a compressed state and clears the noise. /clear wipes it entirely. You use /compact when you want to preserve context and keep going. You use /clear when you're switching tasks. You use /usage to see how close you are before things degrade.

# Check before you hit the wall
/usage
/stats

# Compress without losing context
/compact

# Full reset between tasks
/clear

None of this is hard. It's just not the first thing most people think about because they're focused on the prompt, not the session state. The session state is where the problems actually live.

CLAUDE.md is where you put what the model should never forget

Context windows reset between sessions. The model doesn't remember your tech stack, your constraints, your preferences. Every new session starts cold.

CLAUDE.md is the file it reads on startup. Standing instructions. Project constraints. Whatever you'd have to re-explain every time if you didn't write it down once.

# CLAUDE.md — Project Rulebook
This project uses Supabase for auth and data.
All database operations use the service role key server-side only.
Never include API keys, service_role keys, or secrets in client-side code.
No placeholders in finished deliverables.
TypeScript strict mode throughout.

If you don't write this file, you'll spend the first several minutes of every session re-briefing the model on things it forgot overnight. If you write it well, you spend those minutes working.

Same logic for agent.md (instructions for sub-agents) and skill.md (encoded workflows). These aren't configuration files. They're how you teach the model your standards and keep them across sessions. The model isn't smart enough to remember. The files are.

Agent teams are experimental and earn the word "teams"

Claude Code can spawn multiple specialized agents — a Researcher, a Strategist, a Reviewer — who communicate with each other directly rather than routing everything through a central coordinator. In practice this means parallel workstreams where one agent's context doesn't contaminate another's.

The useful version: spawn a Researcher to gather external data while a Strategist is mapping the build. They share a task list. Neither sees the other's raw context dump. The Reviewer sees the output of both before anything gets committed.

The feature is experimental, requires a settings.json change, and costs more tokens. It's worth it for complex builds. It's not worth it for anything a single focused agent can handle.

The coordination overhead is real. Each agent runs its own context. Spawning five agents for a task one agent could handle is slower and more expensive. The judgment call is whether the task genuinely benefits from specialization or just feels like it does.

Permissions are not optional reading

Because Claude Code has Bash access, it can do things that are difficult to undo. Delete a file. Install a package that introduces a vulnerability. Make an API call that costs money or exfiltrates data you didn't intend to expose.

You manage this through an allow/deny list in settings.json. Pre-approve reads, git operations, and test runs. Gatekeep package installs, deletes, and external API calls.

{
"permissions": {
"allow": ["read", "git", "test"],
"deny": ["delete", "install", "**/.env", "**/secrets/**"]
}
}

This is not paranoia. This is operating a system with broad file system access like it has broad file system access. The model is not cautious by default. It will do what you asked in the most direct way available.

What it actually costs

Pro is $20/month. Max is $100-200/month. A complex session with agent teams can run $7-8 in tokens. A single focused session on a well-scoped task is significantly less.

The math holds against the alternative, which is the same work done manually or by a contractor billed hourly. The discipline around context management is what keeps the math from breaking. Bloated sessions, poor CLAUDE.md hygiene, and unnecessary agent spawning all drive cost without driving output.

Claude Code is a power tool that requires power-tool habits.

The reward is genuine autonomy on complex builds — the model working while you think about the next thing. The penalty for not developing the habits is sessions that drift, context that rots, and a model that's confidently wrong in ways that take longer to fix than doing it manually would have.

The fundamentals — context hygiene, persistent instructions, scoped permissions — carry across whatever comes next. Learn them now.
