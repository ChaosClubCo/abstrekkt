Product Requirements Document: Pod-AI App

1. Executive Summary

The Pod-AI App is a mobile-first platform enabling users to generate unique AI-powered designs and apply them to print-on-demand products. It integrates with a print fulfillment service (e.g., Printful) to streamline the design-to-delivery process. The app aims to democratize personalized merchandise creation, making it accessible without requiring graphic design expertise.

2. Problem Statement & User Impact

Problem: Individuals often lack the design skills or time to create custom designs for personalized products. Existing design tools are complex, and generic print-on-demand services offer limited customization or require pre-made designs, hindering creative expression and unique gift creation.

User Impact:

  • Casual Users: Face frustration with complex software, leading to abandoned personalization ideas and limited unique product options.
  • Small Businesses/Creators: Incur high costs and time investment in design, hindering rapid product launches and iteration.
  • Pod-AI App Users: The app eliminates the need for design expertise, allowing rapid prototyping and ordering of unique products, enhancing self-expression, gift-giving, and entrepreneurship.

3. Goals & Success Metrics (OKRs)

Objective: Enable users to effortlessly create unique, AI-generated designs and order custom print-on-demand products from their mobile devices.

Key Results:

  • KR 1: Design Creation Engagement: Achieve an average of 5 unique AI design generations per active user per week within three months of launch.
    • Metric: Average AI design generations per active user.
    • Target: > 5
  • KR 2: Conversion Rate: Attain a 5% conversion rate from "design generated" to "product ordered" within six months of launch.
    • Metric: Percentage of users who place an order after generating a design.
    • Target: > 5%
  • KR 3: User Satisfaction (NPS): Achieve a Net Promoter Score (NPS) of 45+ related to the design and ordering experience within six months.
    • Metric: NPS from in-app surveys.
    • Target: > 45
  • KR 4: System Stability & Performance: Maintain an average API response time of less than 300ms for core functionalities (design generation, product catalog, order placement) and 99.9% uptime.
    • Metric: Average API response time and system uptime.
    • Target: < 300ms, 99.9% uptime

4. User Stories & Acceptance Criteria

Authentication & Profile:

  • Sign Up: Users can sign up via email/password or social login (Google, Apple), with secure creation in Supabase Auth, email confirmation, and automatic login.
  • Log In: Users can log in via email/password or social login, receive error messages for invalid credentials, reset passwords, and be securely authenticated.
  • Profile Management: Users can view and edit basic profile information (name, shipping address), with changes saved securely to their Supabase user profile.

AI Design Generation:

  • Generate Designs: Users can input text prompts to generate AI design variations, view progress indicators, and see generated designs clearly displayed and stored securely, linked to their account.
  • Refine Designs: Users can select designs for detail view, regenerate variations, and save favorite designs.

Product Browsing:

  • Browse Products: Users can view a categorized and searchable catalog of print-on-demand products (e.g., t-shirts, mugs, hoodies) from the Printful integration, with details on pricing, sizes, colors, and materials.

Product Customization & Ordering:

  • Apply Design: Users can select a design and a product, preview the design on the product, and adjust its position, size, and rotation within defined boundaries.
  • Add to Cart: Users can specify quantity, size, and color for customized products and add them to a shopping cart, which displays a running total.
  • Review & Place Order: Users can review cart items, edit quantities, proceed to checkout, confirm shipping address and payment method, view calculated shipping costs, and review the final order summary before payment.
  • Secure Payment: Users can make payments via supported methods (e.g., credit card via Stripe), with secure processing. Upon successful payment, an order is created and submitted to Printful, and the user receives confirmation.
  • Order History: Users can view a list of past orders with their status (processing, shipped) and details, including items, designs, shipping addresses, and tracking information.

5. Technical Requirements

Architecture Overview:

  • Mobile Frontend: React Native + Expo app (mobile/)
  • Backend API: Express.js API (backend/)
  • Database & Auth: Supabase (PostgreSQL, Authentication, Realtime, Storage, Edge Functions) (database/)
  • Deployment: Vercel (for admin/web frontend and serverless functions for Express API, or containerized Express backend)

Required APIs:

  • Internal Backend API (Express.js):
    • /api/auth: User registration, login, logout, password reset (Supabase Auth).
    • /api/users: User profile management.
    • /api/ai/generate: Orchestrates calls to external AI image generation service, stores designs.
    • /api/designs: CRUD for user-generated designs.
    • /api/products: Retrieve Printful product catalog, handle product configuration.
    • /api/cart: Manage user's shopping cart state.
    • /api/orders: Create, retrieve, and update user orders (submitting to Printful).
    • /api/payments: Handle payment intent creation and confirmation with Stripe.
    • /api/webhooks/stripe: Endpoint for Stripe payment notifications.
    • /api/webhooks/printful: Endpoint for Printful order status updates.
  • External APIs:
    • AI Image Generation API: (e.g., OpenAI DALL-E, Stability AI, Midjourney) - generateImage(prompt, options). Authentication via API Key.
    • Printful API: getProductCatalog(), getVariantDetails(variantId), calculateShipping(recipientAddress, items), submitOrder(orderData), getOrderStatus(orderId). Authentication via API Key/OAuth.
    • Stripe API: createPaymentIntent(amount, currency), confirmPaymentIntent(paymentIntentId), createWebhookEndpoint(). Authentication via API Key.
    • Supabase Client Libraries: For mobile app to interact with Supabase Auth (directly) and the Express API.

Integrations:

  • Supabase: Authentication, PostgreSQL Database, Row Level Security (RLS), Storage, Edge Functions.
  • Printful: Product catalog, order submission, status updates, shipping calculation.
  • Stripe: Secure payment processing, webhook handling.
  • AI Service Provider: Text-to-image generation.

Proposed Data Models/Schema Definitions (Supabase PostgreSQL):

  • users: Links to Supabase Auth id, email, full_name, shipping_address (JSONB), billing_address (JSONB).
  • designs: id, user_id, prompt, generated_image_url, thumbnail_url, is_public (BOOLEAN), created_at, updated_at.
  • products: id, printful_product_id (INTEGER UNIQUE), name, description, base_price (DECIMAL), image_url, category, metadata (JSONB).
  • orders: id, user_id, printful_order_id (INTEGER), total_amount (DECIMAL), currency, status (TEXT), shipping_address (JSONB), payment_intent_id (TEXT), tracking_number, tracking_url, created_at, updated_at.
  • order_items: id, order_id, product_id, design_id (UUID NULLABLE), printful_variant_id (INTEGER), quantity, price_per_item (DECIMAL), design_placement_metadata (JSONB).
  • payments: id, order_id (UUID NULLABLE), user_id, stripe_charge_id (TEXT UNIQUE), amount (DECIMAL), currency, status (TEXT), method (TEXT), transaction_details (JSONB).

6. Non-Functional Requirements

  • AI Image Generation Latency: Aim for 10-30 seconds, with real-time feedback.

Security:

  • Authentication & Authorization: Supabase Auth, RLS, JWTs.
  • Data Encryption: TLS 1.2+ for transit, Supabase encryption at rest.

Scalability:

  • Backend: Stateless Express API for horizontal scaling (containerization).

Reliability & Availability:

  • Uptime: 99.9% for API and database.
  • Error Handling: Robust error handling and logging (Sentry).

Maintainability & Observability:

  • Code Quality: Standards, unit/integration tests.
  • Monitoring: API performance, errors, database health, external service availability.
  • Logging: Centralized logging.

Usability:

  • Intuitive UI/UX for design and ordering.
  • Mobile-First Design for iOS/Android.

10. Security Considerations (OWASP-Based Checklist)

  • A01: Broken Access Control: Mitigated by Supabase RLS and tRPC protectedProcedure with server-side authorization checks.
  • A02: Cryptographic Failures: Mitigated by HTTPS/TLS 1.2+, Supabase encryption at rest, and secure secrets management via environment variables.
  • A03: Injection: Mitigated by parameterized queries (Supabase client), Zod schema validation in tRPC, and input sanitization.
  • A04: Insecure Design: Mitigated by threat modeling, least privilege principle, and secure defaults.
  • A05: Security Misconfiguration: Mitigated by secure Vercel/Supabase defaults, CI/CD security checks, and strict environment configurations.
  • A06: Vulnerable and Outdated Components: Mitigated by automated dependency scanning and regular updates.
  • A07: Identification and Authentication Failures: Mitigated by Supabase Auth (MFA, hashing, JWTs) and rate limiting on login attempts.
  • A08: Software and Data Integrity Failures: Mitigated by CI/CD integrity checks, signed commits, and webhook signature verification.
  • A09: Security Logging and Monitoring Failures: Mitigated by comprehensive logging (Vercel, Supabase), Sentry, PostHog, and critical alerts.
  • A10: Server-Side Request Forgery (SSRF): Mitigated by strict URL validation and whitelisting for external requests.

    • Product Architecture Document: POD AI App

    1. System Overview

    The POD AI application is a full-stack platform for AI-assisted custom product design and ordering, hosted on Vercel. It utilizes a Next.js 15 (App Router) frontend with tRPC for type-safe API communication. Supabase provides a managed PostgreSQL database, authentication, storage, and real-time capabilities. Stripe handles payments, and external APIs are used for AI generation and print-on-demand fulfillment. Sentry and PostHog are integrated for observability. The architecture is designed for high scalability (100,000+ concurrent users) and security.

    2. Tech Stack

    • Next.js 15 (App Router): Full-stack framework for performant, SEO-friendly UIs and backend logic.
    • tRPC: End-to-end type-safe API layer.
    • Supabase: Managed PostgreSQL, Auth, Storage, Realtime, and RLS.
    • Vercel: Serverless hosting, global CDN, CI/CD.
    • Stripe: Secure payment processing.
    • Sentry: Error tracking and performance monitoring.
    • PostHog: Product analytics and user session recording.

    3. Data Models

    • profiles: Extends Supabase Auth users with full_name, avatar_url, created_at, updated_at.
    • products: id, user_id, name, description, price, image_url, product_data (JSONB for POD specifics), status ('draft', 'published', 'archived'), created_at, updated_at.
    • orders: id, user_id, total_amount, status ('pending', 'processing', 'shipped', 'delivered', 'cancelled'), shipping_address (JSONB), payment_intent_id (Stripe ID), created_at, updated_at.
    • order_items: id, order_id, product_id, quantity, unit_price.
    • images: id, user_id, url (Supabase Storage), file_path, type ('uploaded', 'ai_generated'), prompt (for AI images), metadata (JSONB), created_at.

    4. API Design (tRPC)

    tRPC procedures are implemented for CRUD operations on data models, ensuring type safety between frontend and backend. Examples include product.getById, product.getUserProducts, product.create, and order.create.

    5. Authentication & Authorization

    • Supabase Auth: Manages user sign-up, login (email/password, OAuth), and JWT issuance.
    • JWT Handling: JWTs are stored securely client-side and sent with API requests.
    • Row Level Security (RLS): Applied to all tables (profiles, products, orders, order_items, images) to enforce data access policies based on authenticated user IDs.
    • tRPC protectedProcedure: Ensures API endpoints are only accessible by authenticated users.

    6. Security Architecture

    • OWASP Top 10 Mitigation: Addressed through RLS, input validation (Zod), secure secrets management, dependency scanning, and comprehensive logging/monitoring.
    • Data Encryption:
      • At Rest: Supabase PostgreSQL and Storage are encrypted at rest.
      • In Transit: HTTPS/TLS 1.2+ enforced for all communications.
    • Secrets Management: Stored securely in Vercel Environment Variables and Supabase project settings, adhering to the principle of least privilege.

    7. Scalability & Performance

    • Caching Strategy: Next.js Data Cache (fetch cache), Vercel Edge Config, Supabase Storage CDN, and browser caching are utilized.
    • Handling 100K+ Concurrent Users: Achieved via Vercel's auto-scaling serverless functions and global CDN, Supabase's managed PostgreSQL with connection pooling (PgBouncer), and stateless service design.
    • Potential Bottlenecks: Database hotspots, external API rate limits, serverless cold starts, and network latency are identified and mitigated through optimization, caching, and monitoring.

    8. Deployment Pipeline

    • CI/CD Flow: GitHub Actions for linting/testing, Vercel for automated preview and production deployments.
    • Environment Staging: Local development, Vercel Preview (staging Supabase project), and Production (production Supabase project).
    • Automated Rollback: Vercel's immutable deployments allow one-click rollbacks. Git reverts and Supabase database backups provide additional recovery options.

    9. Observability

    • Logging: Vercel logs, Supabase logs, structured logging in API routes, and client-side logging.
    • Metrics: Vercel Analytics, Sentry Performance Monitoring, PostHog Product Analytics, Supabase metrics.
    • Tracing: Sentry distributed tracing and correlation IDs for end-to-end request tracking.
    • Critical Alerts: Configured in Sentry, Supabase, PostHog, and Vercel for error rates, performance degradation, security events, and critical business metrics.

    10. Architecture Decision Records (ADRs)

    • ADR 001: Adopt tRPC for API Layer: Chosen for end-to-end type safety, improved DX, and performance.
    • ADR 002: Supabase as Backend-as-a-Service: Selected for managed PostgreSQL, integrated Auth, Storage, RLS, reducing operational overhead and accelerating development.
    • ADR 003: Next.js 15 App Router and Vercel Hosting: Chosen for performance (RSC, fetch caching), unified full-stack development, and automatic scalability.

    11. Trade-offs

    • Vendor Lock-in vs. Speed to Market/Reduced Ops: Managed services (Supabase, Vercel) accelerate development but create dependencies.
    • Serverless Architecture vs. Dedicated Servers: Serverless offers automatic scaling and cost-efficiency for fluctuating traffic but less control and potential cold starts.
    • Tightly Coupled Stack vs. Microservices: The Next.js/tRPC/Supabase stack offers high DX and efficiency for a focused team but less flexibility than a polyglot microservices approach.
    • SQL (PostgreSQL) vs. NoSQL: PostgreSQL is chosen for its data integrity and relational capabilities, suitable for transactional data, over NoSQL's potential for extreme horizontal scaling with unstructured data.
