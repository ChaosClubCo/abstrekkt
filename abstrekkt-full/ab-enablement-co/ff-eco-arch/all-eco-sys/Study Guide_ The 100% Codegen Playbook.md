### Study Guide: The 100% Codegen Playbook

This study guide provides a comprehensive review of the shift from manual software engineering to 100% code generation. It explores the transition of human roles from code authors to verification engineers, the structure of multi-agent compiler stacks, and the governance frameworks required to secure AI-generated software.

#### Part 2: Quiz Answer Key

**1\. What does "100% code generation" signify in the context of modern software development?**  It signifies treating application code as a disposable "build artifact" generated from specifications, rather than a manually edited source file. This approach expands the scope of automation from simple stubs and API clients to entire systems, refactors, and migrations.**2\. How does the role of a human developer change in a 100% codegen environment?**  The human role shifts from a "software engineer" focused on manual typing and code authoring to a "verification engineer." The primary responsibility becomes defining the "skills" and policies that guide AI agents and proving that the resulting output is correct and secure.**3\. What are the specific components that humans are responsible for authoring in this new paradigm?**  Humans author executable specifications (requirements and constraints), test intent (invariants and properties), and high-level policies regarding security and compliance. Additionally, they create "skills," which are structured markdown documents that provide instructions and toolsets for AI agents.**4\. Describe the "Multi-Agent Compiler Stack" concept.**  The stack treats code generation as a stateful, distributed system similar to a compiler toolchain with deterministic inputs and reproducible outputs. It utilizes specialized agent roles—such as Spec, Planner, Coder, and Reviewer—to manage different stages of the software development lifecycle.**5\. Why is a "Failure Protocol" a critical component of a SKILL.md file?**  The Failure Protocol defines the feedback loop by telling an agent how to react when things go wrong, such as triggering a debugger or requesting a spec clarification. This allows the orchestrator to route errors to the correct agent automatically without the need for manual retry logic.**6\. What is "test-gaming," and how does the Test Agent skill address it?**  Test-gaming occurs when AI agents produce code that passes weak tests but misses the actual intent or introduces flaws. The Test Agent skill prevents this by explicitly forbidding tests that only assert a function returns its output and by requiring tests to assert high-level spec intent.**7\. Why does the document emphasize that SBOMs (Software Bill of Materials) must be generated at build time?**  Generating SBOMs at build time ensures that the inventory of components and dependencies is accurate and carries full provenance. Following NIST warnings, the text notes that retroactive SBOM generation lacks the same level of security and auditability.**8\. Explain the "Strangler Pattern" as it relates to the migration plan for code generation.**  During the expansion phase of migration, the Strangler Pattern involves placing stable interfaces in front of manual code and then replacing the underlying implementations with generated code. Eventually, the manual code is deleted entirely, and the generated directory becomes the primary codebase.**9\. What are the primary legal risks associated with AI-generated code mentioned in the text?**  The text highlights that AI outputs may be non-copyrightable because the U.S. Copyright Office requires human authorship. Furthermore, model outputs can be "strikingly similar" to open-source code, potentially leading to licensing conflicts and lack of proper attribution.**10\. What are "Golden Tests," and what role do they play in the testing ecosystem?**  Golden tests lock down existing behavior to ensure consistency during migrations or refactors. They provide a baseline for human review by flagging "golden drift," which occurs when the generated output deviates beyond an acceptable threshold from the original behavior.

#### Part 4: Glossary of Key Terms

Term,Definition  
100% Code Generation,"A development paradigm where human-authored specifications and ""skills"" drive AI agents to produce all source files as disposable build artifacts."  
Build Artifact,"Code that is generated from a higher-level source (like a spec) and is marked ""DO NOT EDIT,"" similar to Protocol Buffers or OpenAPI outputs."  
Failure Protocol,"A section within a Skill definition that instructs an agent on how to handle errors, such as requesting clarification or triggering a different agent role."  
Golden Test,"A testing method used to lock in behavior by comparing current outputs against a ""golden"" reference to detect unintended changes or ""drift."""  
Idempotency,"The property where a generation process produces the exact same artifacts every time if the inputs (specs, skills, model config) remain unchanged."  
Multi-Agent Compiler Stack,"A toolchain of specialized AI agents (e.g., Planner, Coder, Security) that collaborate to transform high-level requirements into deployable software."  
Property-Based Testing,"A testing strategy (e.g., using Hypothesis) that tests code against a wide range of generated inputs to catch assumptions or ""hallucinations"" in logic."  
Provenance,"Documented evidence of a software's origin, including the commit hash, input hashes, skill versions, and model configurations used during build."  
SBOM (Software Bill of Materials),"A comprehensive inventory of all dependencies and components within a software package, ideally generated at build time."  
SKILL.md,"A structured markdown document authored by humans that defines an agent's role, inputs, outputs, constraints, and success criteria."  
Strangler Pattern,A migration strategy used to gradually replace manual code with generated code by wrapping legacy logic in stable interfaces.  
Test-Gaming,A failure mode where AI-generated code passes tests by fulfilling the literal test requirements while failing to implement the actual intended logic.  
Verification Engineer,"The evolving role of the software developer, focused on proving code correctness and security through policies and automated gates rather than writing code."
