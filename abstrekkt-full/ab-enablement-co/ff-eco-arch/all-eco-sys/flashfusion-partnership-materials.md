### Responsible-Use Checklist (10 items, plain language)

**Claude at Work — Responsible Use Checklist**

Before you use Claude for work tasks, check off each item:

- [ ] **1. No customer personal data in prompts.** Don't paste customer names, addresses, phone numbers, or account numbers into Claude unless your company has explicitly approved it.
- [ ] **2. No internal passwords, credentials, or API keys.** Claude doesn't need them and storing them in a chat creates a risk.
- [ ] **3. Verify anything Claude writes before you send it.** Claude makes mistakes. Read the output before it goes to a customer or your boss.
- [ ] **4. Don't represent Claude's output as your own expert opinion.** If Claude writes a legal or medical or financial answer, say you used an AI tool.
- [ ] **5. You're responsible for what you submit.** Claude is a tool. If you paste something confidential, that's on you, not Claude.
- [ ] **6. Check your company's AI policy.** Some employers have rules about which AI tools are approved. Know your policy before you start.
- [ ] **7. Don't use Claude to make decisions about people.** Hiring, firing, performance ratings — keep humans in the loop.
- [ ] **8. Save your CLAUDE.md somewhere safe.** It's your configuration file. Back it up.
- [ ] **9. If it feels wrong, don't send it.** If Claude's output makes a claim you can't verify, don't pass it along.
- [ ] **10. Report errors.** If Claude gives you something harmful or wrong, use the thumbs down button. That feedback matters.

## Post 2: "What CLAUDE.md taught me about teaching beginners"

I've been building with Claude Code long enough that CLAUDE.md feels obvious to me.

The sticking point wasn't technical. It was conceptual: the idea that you can give a tool persistent context about who you are and what you need — and that it remembers that context across sessions.

## Post 3: "Same problem, two tools: Claude Code vs Base44 for operators"

I've built production work in both. Here's the actual tradeoff for a non-developer operator:

**Base44** is fast and immediate. You describe what you want, it builds a working UI, you can deploy in an afternoon. The output is a standalone app. The cost is that you're building on someone else's platform — you're configuring, not engineering. When you hit the edges of what Base44 does, you're stuck.

**Claude Code** is slower to start and requires comfort with a terminal. The output is a system you understand and can modify. When something breaks, you can fix it. When you want to extend it, you extend it. The cost is the learning curve — and it's real.

For a dispatcher who needs a scheduling assistant: Base44. Faster time to working, lower complexity, no need to touch infrastructure.

For someone building a client-facing product or an agent system that needs to evolve: Claude Code. The floor is higher but the ceiling is much higher.

I use both. Most of my Base44 work is for prototyping and internal tooling at INT. Most of my Claude Code work is for client deliverables and the FlashFusion stack.

The mistake I see non-technical people make: choosing Claude Code because it sounds more serious, then getting stuck in the learning curve and shipping nothing.

Choose the tool that ships. You can migrate later.

## Post 4: "What actually breaks when nontraditional builders try AI"

Not the technical part.

The people I work with — service techs, shop owners, office managers — can learn the technical part. CLAUDE.md is a text file. Claude Code runs in a terminal. The mechanical steps aren't the barrier.

Here's what actually breaks:

**Confidence calibration.** When Claude gets something wrong — and it will — non-technical people tend to blame themselves. "I must have asked wrong." Sometimes that's true. More often Claude just hallucinated and needs to be corrected. Getting to the point where you push back on the output without second-guessing yourself takes time.

**Use case selection.** The first instinct is usually too big. "I want to automate my entire customer communication workflow." That's a six-month project. Starting with "I want to draft follow-up emails for late payments" is a six-minute project. The pattern recognition for what's achievable in an afternoon vs. what's a months-long build doesn't develop until you've built something a few times.

**The blank page problem.** Claude is a general-purpose tool. When you open a session with no CLAUDE.md and no prompt engineering, the output is generic. Most people who "tried AI and it didn't do anything useful" are describing this experience — they opened the tool without briefing it. The fix is CLAUDE.md. The problem is nobody tells them that.

These are solvable. They just require someone who has run into all three walls already to explain them.

That's the workshop I'm building.
