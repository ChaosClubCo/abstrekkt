PROMPT 03: THE ARCHITECTURE-FIRST SPEC
=========================================
Stop Claude from jumping to code. Force it to think in systems first.

WHEN TO USE:
- Before building any app, API, service, or automation
- When you need to understand tradeoffs before committing to a stack
- Architecture reviews, technical planning, system design

THE PROMPT:
-----------

Before writing any code or implementation details, produce an architecture
spec covering:

1. SYSTEM BOUNDARIES: What's in scope vs. out of scope? What does this
   system own vs. delegate to external services?

2. DATA FLOW: How does data enter, transform, and exit the system?
   Include auth boundaries and trust zones.

3. STATE TRANSITIONS: What are the key states? What triggers transitions?
   Where can things get stuck?

4. FAILURE MODES: What breaks first under load? What happens when a
   dependency goes down? What's the blast radius of each failure?

5. SECURITY SURFACE: Where does untrusted input enter? What needs
   validation, rate limiting, or access control? What's the auth model?

6. SCALE CEILING: At what point does this design stop working? What's
   the first bottleneck you'd hit at 10x current load?

Present 2-3 architectural approaches with explicit tradeoffs:
(security vs. complexity, cost vs. performance, speed-to-ship vs. extensibility)

Then recommend ONE approach with a clear justification.

WHY IT WORKS:
Engineers waste days building the wrong thing because they started coding
before they understood the system shape. This prompt mirrors how staff+
engineers actually think: boundaries first, then data flow, then failure
modes, then implementation.

VARIATIONS:
- For APIs: Add "7. CONTRACT: Define request/response shapes, status codes,
  and error formats before implementation."
- For automations: Add "7. IDEMPOTENCY: What happens if this runs twice?
  Can it recover from partial execution?"
- For migrations: Add "7. ROLLBACK: How do we undo this if it goes wrong?
  What's the point of no return?"

PRO TIP:
After getting the architecture spec, paste it back as context for your
implementation prompt: "Given this architecture [paste], implement
component X. Do not deviate from the boundaries defined above."
