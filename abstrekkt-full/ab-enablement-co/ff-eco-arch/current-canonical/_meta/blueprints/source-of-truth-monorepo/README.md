# Source-of-Truth Monorepo Blueprint (ZIP_SPEC)

> Reconstructed from source chat
> `Portfolio consolidation and source-of-truth monorepo setup` (uuid `5a0b8c0b…`, batch-0001).
> The source consolidated a sprawling personal portfolio — **385 GitHub repos and
> 130+ deployed apps across 10 platforms** (Base44, Lovable, Vercel, Replit, Bolt,
> Blink, Google Cloud Run, Netlify, v0.dev, GitHub) — into a single Turborepo +
> pnpm monorepo, with import/archive automation, CI/CD, governance, and a
> board-ready consolidation plan. This package materializes that blueprint as a
> working, scaffoldable monorepo skeleton plus the scripts and docs to run the
> migration safely.

## 1. Executive Summary

A **runnable monorepo skeleton and migration toolkit** that turns a fragmented,
multi-platform portfolio into one governed source of truth. The owner (a Staff
Engineer, AppSec + Platform) was spending ~40 hrs/month maintaining 385 repos
scattered across 10 build platforms, with **40 apps stranded on cancelled
platforms** (Base44, Bolt). The blueprint consolidates to ~130 active repos under
a Turborepo/pnpm workspace, archives ~250, and adds CI/CD, security scanning, and
a CODEOWNERS governance model.

This package ships the **actual files** the source described: root
`package.json`, `pnpm-workspace.yaml`, `turbo.json`, `tsconfig.base.json`, the
`.github/workflows/ci.yml` pipeline, three migration scripts (`import-repo.sh`,
`archive-repo.sh`, `consolidate.py`), a sample `IMPORT_PLAN.csv`, `CODEOWNERS`,
and the directory map. Numbers from the source (65% repo reduction, ~$30K/year
savings, 4-week 3-phase plan) are preserved as **claims**, not as guarantees —
see the CLAIMS CHECK. All originally-unverified figures (build times, CI success
rate, coverage) are kept labelled "Unknown → Target," matching the source.

## 2. Build

Scaffold the monorepo from this blueprint:

```bash
# 1. Create the target monorepo (or cd into an existing empty one)
mkdir source-of-truth-monorepo && cd source-of-truth-monorepo
git init

# 2. Copy the blueprint's config + scripts in
cp /path/to/source-of-truth-monorepo-blueprint/monorepo/* .
cp -r /path/to/source-of-truth-monorepo-blueprint/scripts ./scripts
cp /path/to/source-of-truth-monorepo-blueprint/ci/ci.yml .github/workflows/ci.yml

# 3. Create the directory skeleton
bash scripts/init-structure.sh

# 4. Install the toolchain (pnpm + turbo are declared in package.json)
corepack enable
pnpm install

# 5. Dry-run the consolidation (NO clones, NO writes — prints the plan)
python3 scripts/consolidate.py --plan IMPORT_PLAN.csv --dry-run

# 6. Quality gate
pnpm turbo run lint test build
```

> SAFETY: every script defaults to **dry-run / explicit-confirm**. None of them
> auto-clone or auto-execute code from imported repositories. Review
> `docs/SECURITY.md` before running against real repos.

```
                    ┌──────────────────┴───────────────────┐
                    ▼                                       ▼
        CI/CD: GitHub Actions                    GOVERNANCE
        install → lint → test → build → audit    CODEOWNERS, branch protection,
        Dependabot · CodeQL · Snyk               Renovate/Dependabot, semver
                    │

        Deploy: Vercel (primary) · Cloud Run (secondary)
```

Three honest design constraints carried from source:
1. **Most metrics are baselines, not measurements** — build time, CI success
   rate, and coverage are "Unknown → Target" in the source and stay that way here.
2. **Consolidation can *increase* complexity** if repos have incompatible
   dependency trees — pnpm workspace isolation + incremental import is the hedge.
3. **Aggressive archival (~250 repos) risks deleting valuable experiments** —
   archival uses bare clones (full history) + GitHub archive, never deletion.

## 6. Implementation Considerations

- **Phased, never big-bang.** Source plan: Phase 1 (Week 1) = 32 P0 repos +
  CI/CD; Phase 2 (Weeks 2–3) = ~63 more; Phase 3 (Week 4+) = archive ~250 +
  governance. Import one repo, run tests, then the next.
- **Standardize the stack on the way in.** Source target: Next.js 15 + React +
  Tailwind, tRPC, Supabase (PostgreSQL + RLS), Supabase Auth, Vercel primary /
  Cloud Run secondary. Don't import 4 auth systems and 4 deploy platforms as-is.
- **Preserve history selectively.** `git filter-repo --to-subdirectory-filter`
  for P0 only (set `PRESERVE_HISTORY=true`); P1–P3 record `original_repo` in
  `package.json` instead. History preservation is slow.
- **Keep originals until Phase 3.** Archival is the *last* step; until then the
  source repos are the rollback.

## 7. Performance / Security Notes

- **Untrusted code on import.** Imported repos are third-party-equivalent until
  reviewed. The scripts copy with `rsync --exclude='.git'` and never run
  `postinstall`/build of imported code automatically. Run `pnpm install
  --ignore-scripts` first, review, then unlock. (See `docs/SECURITY.md`.)
- **No secrets in artifacts.** The source pasted live `.app`/`.host` URLs and
  said "use my credentials"; this package contains **zero credentials**. Any
  token is an `.env` placeholder with a comment. `gh` auth and Turborepo remote
  cache tokens come from the environment, never the repo.
- **Caching claims are conditional.** "2-min incremental / 5-min CI" only holds
  if `turbo.json` task inputs/outputs are correct *and* remote cache is wired —
  benchmark after Phase 1 rather than quoting them as fact.
- **Security gates are advisory until enforced.** Dependabot/CodeQL/Snyk must be
  set to **block merge on critical** in branch protection, or they're just noise.
- **GitHub rate limits.** Batch imports sleep between clones; use an authenticated
  `gh`/App token. The driver caps concurrency at 1 by default.

## 9. Rollback Notes

- **Per-import rollback:** an import is just files copied under `projects/**`.
  `git checkout -- projects/<dir>` or delete the directory; the source repo is
  untouched (still on GitHub).
- **Archival rollback:** `archive/<date>/<repo>` is a `--bare`/`--mirror` clone.
  Restore with `git clone --mirror archive/<date>/<repo> restored-repo`. GitHub
  archive is reversible (un-archive in repo settings).
- **Stack-standardization rollback:** keep the original `package.json` recorded as
  `original_repo`; revert dependency unification per-package, not globally.
- **Full abort:** because Phase 3 (archival) is last, aborting before it leaves
  every source repo live. Delete the monorepo and nothing is lost.

## 12. Risk Checklist

| Risk | Status in blueprint |
|------|---------------------|
| Auth gaps | Source mixes Supabase Auth + NextAuth across repos; target standardizes on Supabase Auth — **enforce on import**, don't carry 4 systems. |
| Secrets handling | Source pasted live URLs + "use my credentials"; package ships **zero secrets**, `.env` placeholders only, `--ignore-scripts` on first install. |
| Tenant isolation | Multi-tenant SaaS (FlashFusion) relies on Supabase **RLS** — verify RLS policies survive import; flagged in `docs/SECURITY.md`. |
| Rate limiting | App-level limiting unverified per app; import driver itself rate-limits GitHub clones (sleep + concurrency 1). |
| Observability | "Unknown" baselines for CI success/MTTR — instrument before quoting metrics. |
| Rollback | Documented (§9): per-import checkout, bare-clone restore, originals kept until Phase 3. |
| Dependency drift | Root cause of the project; pnpm single lockfile + Renovate/Dependabot, but **incompatible trees may break apps** — incremental import. |
| Missing tests | Coverage is aspirational (≥70% target, current unknown); many imported repos have **no tests** — gate accordingly. |
| Unclear ownership | CODEOWNERS references teams (`@core-team`, `@app-team`) that **must exist** in the org or rules silently no-op. |
| Contradictions | Savings figure ($51.3K vs $30K) and duplicate repos surfaced, not smoothed. |
