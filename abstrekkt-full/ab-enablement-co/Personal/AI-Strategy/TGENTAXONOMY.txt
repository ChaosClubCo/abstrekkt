1.1 Difference between exhaustive subcategories and canonical list plus tags
- Exhaustive subcategory list
- Structure: every real-world variant appears as its own node in the hierarchy.
- Pros: immediate discoverability; simple UI tiles and presets; fewer runtime lookups; better for static menus and explicit product presets.
- Cons: large, rigid taxonomy; harder to maintain; potential duplication across categories; UI can become crowded.
- Canonical list + tag-driven variations
- Structure: a smaller set of parent subcategories (canonical types) with flexible metadata tags that describe variants (fit, wash, gender, mockup).
- Pros: smaller, easier-to-maintain taxonomy; flexible faceted search; easier to add new variants without structural changes.
- Cons: requires tag system and faceted UI; some presets or explicit menu items must be generated on the fly; slightly more runtime logic.
- Recommendation for your product: Use a hybrid — keep an exhaustive set for high-frequency presets (Tees, Hoodies, Jeans variants) and implement tags for long tail variants and cross-cutting attributes to keep the system extensible and performant.

2. Create New wizard design (guided + post-MVP creator)
- Phase 1 MVP behavior
- Guided wizard with 4 compact steps:
- Select Base Category: pick major category (Apparel, Accessories, etc.)
- Choose Canonical Type: select base (T-Shirt, Hoodie, Pants)
- Auto-suggest Tags: system proposes tags from Brand Kit (style, gender, sizes, mockup types, print areas)
- Review & Save: name, default size set, default mockup; Save as preset
- Smart suggestions: populate fabric, mockup type, and print areas using Brand Kit contrast, color palette, and allowed logo areas
- Outputs: saved preset with unique ID, derived tags, and default mockup templates
- Post-MVP behavior
- Full custom builder: add/remove tags, upload custom mockup templates, set production constraints, set default pricing tiers, and versioning for audit logs
- Shareable presets and marketplace for community presets
- Preset inheritance and rollback (audit-ready)
- UI affordances
- Inline preview mockup, quick toggles for Gender/Size/Mockup, provenance metadata (creator, createdAt), and option to clone an existing preset to start faster

Below is a compact, production-ready design for a canonical list + tag-driven product taxonomy with hybrid presets. It includes the data model, tag taxonomy, preset rules, UI/faceted-search behavior, and small export examples (JSON, YAML, Markdown) you can ingest as seed data.

Data model (canonical + tags)
- Category (id, name, order, uiIcon)
- CanonicalType (id, categoryId, name, defaultMockups[], defaultPrintAreas[], highFrequencyFlag)
- VariantTag (id, namespace, key, value)
- Preset (id, canonicalTypeId  custom, name, tags[], defaultSizes[], mockups[], createdBy, createdAt, isExhaustive)
- MockupTemplate (id, type, orientation, previewUrl, recommendedPrintArea)
- TagAssignment (entityId, entityType, tagId)
- AuditMeta (entityId, changeType, actorId, timestamp, version)
Key relationships:
- CanonicalType belongs to Category.
- Presets reference a CanonicalType and an array of VariantTags.
- Tags are namespaced (e.g., fit:skinny, wash:vintage, gender:mens).

Tag taxonomy (namespaces and example values)
- gender: men; women; unisex; kids; baby
- fit: skinny; slim; regular; relaxed; loose; wide
- rise: low; mid; high
- wash: raw; stonewash; acid; vintage; distressed; tie-dye
- sleeve: short; long; sleeveless; 3/4
- neckline: crew; v-neck; henley; polo
- material: cotton; organic-cotton; polyester; fleece; denim; linen; corduroy
- mockup: model-front; model-lifestyle; hanging; flatlay; on-hanger; 360-rotating
- printArea: front; back; sleeve; full-wrap; hem-tag
- embellishment: embroidery; patch; foil; screen-print; sublimation
- sizeRange: XS-XL; XS-4XL; newborn-24m; kids-2-12
- style: lifestyle; urban; athletic; vintage; premium; budget
- productCondition: pre-shrunk; pre-washed; raw-edge
- sustainability: recycled; organic; low-water; certified
- priceTier: budget; mid; premium
Naming convention: namespace:key (e.g., fit:relaxed). Use a controlled vocabulary service for management UI.

Preset strategy (hybrid)
- High-frequency presets (explicit, exhaustive)
- Examples: tee_basic_hanging; tee_vintage_lifestyle; hoodie_zip; jeans_modern; sweatshirt_lifestyle
- Implementation: stored as Preset.isExhaustive = true, surfaced in main UI grid as fixed tiles.
- Long-tail variants (tag-driven)
- Examples: pants -> canonicalType = Pants; tags = [fit:bell-bottom, material:denim, style:vintage, gender:women]
- Implementation: built on-the-fly preset generation using canonicalType + tags; saved as user presets when needed.
- Migration path: seed high-frequency presets first, then enable tag-driven creation and faceting in parallel.

UI behavior and faceted search
- Canonical browse: top-level Category -> CanonicalType tiles (default mockups shown). Exhaustive presets appear in a “Popular” strip.
- Faceted filter panel: show tag namespaces with counts (gender, fit, wash, mockup, priceTier, sustainability). Selecting tags composes AND rules within namespace, OR across values, with clear UX microcopy.
- Preset creation: guided wizard pre-fills tags from Brand Kit (color palette → suggested mockups; logos allowed → printArea suggestions). Post-MVP allow users to create fully custom tags and mockups.
- Preset caching: materialize commonly generated tag combinations into cached presets for performance and analytics.
- Mockup selection: present recommended mockup types prioritized by preset.tags.mockup and Brand Kit constraints.
