## Database Schema (Migration 023)

### New Tables

| Table | Purpose | Key Features |
|-------|---------|--------------|
| `prediction_models` | ML model metadata | Versioning, config, metrics, artifacts |
| `usage_predictions` | Time-series forecasts | Values, bounds, trends, actuals |
| `quota_predictions` | Quota exhaustion | Days remaining, recommendations |
| `seasonal_patterns` | Usage patterns | Hourly/daily/weekly/monthly cycles |
| `usage_anomalies` | Anomaly detection | Type, severity, root cause, feedback |
| `prediction_requests` | Queue for predictions | Priority, status, retry logic |
| `prediction_accuracy` | Model accuracy tracking | MAPE, RMSE, MAE over time |
| `forecast_scenarios` | What-if analysis | Adjustments, scenario values |

### Key Functions

```sql
-- Generate usage forecast
generate_usage_forecast(tenant_id, metric_key, horizon_days, model_slug)
  → Returns prediction_date, predicted_value, lower_bound, upper_bound, trend

-- Predict quota exhaustion
predict_quota_exhaustion(tenant_id, quota_type, quota_limit, current_usage)
  → Returns days_until_exhaustion, predicted_date, probability, recommended_action

-- Detect anomaly using z-score
detect_usage_anomaly(tenant_id, metric_key, value, threshold_std)
  → Returns anomaly_id if detected, null otherwise

-- Backfill actuals for accuracy calculation
backfill_prediction_actuals()
  → Returns count of updated predictions

-- Calculate model accuracy
calculate_model_accuracy(model_id, start_date, end_date)
  → Returns MAPE, RMSE, MAE, counts
```

### Model Types Supported

| Type | Description | Config Example |
|------|-------------|----------------|
| `prophet` | Facebook Prophet | `{ "seasonality_mode": "multiplicative" }` |
| `arima` | ARIMA/SARIMA | `{ "p": 1, "d": 1, "q": 1, "seasonal": true }` |
| `exponential` | Holt-Winters | `{ "trend": "add", "seasonal": "mul" }` |
| `linear` | Linear regression | `{ "regularization": "l2" }` |
| `gradient_boost` | XGBoost/LightGBM | `{ "n_estimators": 100 }` |
| `neural` | Neural network | `{ "layers": [64, 32] }` |
| `ensemble` | Model ensemble | `{ "models": ["prophet", "arima"] }` |
| `heuristic` | Rule-based | `{ "method": "moving_average" }` |

## ML Model Pipeline

### 1. Data Collection
```
live_metrics → usage_predictions (historical)
            → seasonal_patterns (detected)
```

### 2. Model Training
```
Edge Function triggers:
1. Collect historical data (90+ days)
2. Detect seasonality
3. Train model (Prophet/ARIMA)
4. Validate with holdout
5. Store model artifacts
6. Update prediction_models
```

### 3. Prediction Generation
```
generate_usage_forecast() →
1. Load production model
2. Get recent trend data
3. Apply seasonality
4. Generate forecast
5. Calculate confidence intervals
6. Store in usage_predictions
```

### 4. Accuracy Tracking
```
backfill_prediction_actuals() →
1. Match predictions with actual values
2. Calculate prediction_error
3. Aggregate into prediction_accuracy
4. Update model metrics
```

## Anomaly Detection Algorithm

### Z-Score Method (Default)

```sql
-- Calculate z-score
z_score = (observed_value - mean) / stddev

-- Classify severity
critical: |z_score| >= 5
high:     |z_score| >= 4
medium:   |z_score| >= 3
low:      |z_score| >= 2
```

### Anomaly Types

| Type | Trigger |
|------|---------|
| `spike` | z_score > threshold |
| `drop` | z_score < -threshold |
| `trend_change` | Trend direction change |
| `seasonality_break` | Pattern deviation |
| `outlier` | Statistical outlier |
| `zero_usage` | Unexpected zero |
| `missing_data` | Data gap |

## Deployment

### 1. Apply Migration

```bash
supabase migration up 023_usage_predictions
```

### 2. Deploy Edge Function (Optional)

```bash
# For Prophet model
supabase functions deploy prophet-forecast
```

### 3. Configure Scheduled Jobs

```sql
-- Schedule daily forecast generation
SELECT cron.schedule(
  'daily-forecast',
  '0 2 * * *',  -- 2 AM daily
  $$SELECT generate_usage_forecast(
    tenant_id, 'api_calls', 30, 'default-prophet'
  ) FROM tenants WHERE is_active = true$$
);

-- Schedule hourly anomaly scan
SELECT cron.schedule(
  'hourly-anomaly-scan',
  '0 * * * *',  -- Every hour
  $$SELECT detect_usage_anomaly(
    tenant_id, metric_key, current_value, 3
  ) FROM live_metrics$$
);

-- Schedule daily accuracy backfill
SELECT cron.schedule(
  'daily-accuracy-backfill',
  '0 3 * * *',  -- 3 AM daily
  $$SELECT backfill_prediction_actuals()$$
);
```

2. **Training Data**: Minimum 30 days recommended for accurate forecasts
3. **Real-time Detection**: Anomaly detection runs on-demand, not streaming
4. **Model Size**: Large models may require external storage
