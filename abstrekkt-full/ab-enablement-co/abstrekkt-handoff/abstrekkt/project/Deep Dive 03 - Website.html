02

Secrets in the browser bundle

CRITICAL

lib/env.ts exposes API keys and the service-role key client-side

Vite inlines every VITE_-prefixed variable into the browser bundle. This config surfaces all of them — and references the Supabase service-role key (which bypasses row-level security) in the same browser-loaded module.

lib/env.ts — all of these become public if setVITE_ANTHROPIC_API_KEY, VITE_OPENAI_API_KEY,
VITE_GITHUB_TOKEN, VITE_STABILITY_API_KEY,
SUPABASE_SERVICE_ROLE_KEY  // service role = bypasses RLS, in a client config

Anyone who opens DevTools on the deployed Vite app reads these. LLM keys can be drained; the GitHub token can touch repos; the service-role key can read/write the whole database. This single file is the most serious issue across all three artifacts.

✓ RESOLVED — lib/env.ts deleted; no VITE_-prefixed secrets remain; .env.production.template removed and docs/checklist corrected to public-vs-server split. Secrets stay server-side in apps/site actions. Live in remediation/clean/website.

MEDIUM

CSP allows unsafe-inline and unsafe-eval

The Next.js middleware sets a thoughtful CSP — good — but script-src permits 'unsafe-inline' and 'unsafe-eval', which substantially weakens its XSS protection. (Partly driven by GA; worth tightening with nonces.)

CREDIT

The Next.js side does secrets correctly

By contrast, apps/site/app/actions.ts is a model server action: 'use server', zod validation, the service-role key read only server-side, a dedupe cookie, IP/UA capture. The right pattern already exists in the repo — the Vite config simply ignores it.

03

Quality & design

CREDIT

Real production hygiene

CI workflows for CodeQL, gitleaks secret-scanning, Supabase RLS tests, and a dependency audit; env templating; multi-domain deploy configs (Vercel/Netlify/Render). This is the most ops-mature of the three by a wide margin.

MEDIUM

Dead analytics in a server action

submitLead guards its gtag call with typeof window !== 'undefined' — but it's a 'use server' function where window never exists. The conversion event is silently never sent.

MEDIUM

Generic-SaaS visual language

The brand is a tri-color gradient (orange #FF7B00 + cyan #00B4D8 + pink #E91E63): gradient-wash hero, blurred color blobs in the corners, Inter body text. Competent, but indistinguishable from a thousand other AI-tool landing pages — and a third, unrelated palette versus Files 01 and 02.

MEDIUM

~60 narration docs / 35,000+ lines

The worst doc-bloat of the set, including paired status files (BACK_NAVIGATION_ADDED.md and BACK_NAVIGATION_COMPLETE.md), COMPLETE_USER_WORKFLOWS…md (3,073 ln), and FIGMA_PROTOTYPE_COMPLETE_ANALYSIS.md (1,827). Most of the 18 MB is prose and embedded rasters, not app.

04

What this file needs

  1. Rotate every key, then move them server-side

    Assume the keys in lib/env.ts are compromised: rotate the Anthropic/OpenAI/GitHub/service-role credentials now. Never prefix a secret with VITE_; proxy all secret-bearing calls through server actions like actions.ts already does.

  2. Pick one app and delete the others

    Keep apps/site (Next.js). Remove the abandoned Vite src/core SPA and the off-domain components/studio audio marketplace.

  3. Tighten the CSP

    Replace unsafe-inline/unsafe-eval with nonces or hashes; load GA via a nonce'd tag.

  4. Fix lead-conversion tracking

    Fire the analytics event from the client after the action resolves, not inside the server function.

  5. Commit to a real brand

    Choose one FlashFusion palette + type system and align it with Files 01–02. Drop the generic tri-gradient or make it genuinely yours.

  6. Purge the status docs

    One README, one architecture doc, one deploy guide. Delete the "ADDED/COMPLETE" pairs.
