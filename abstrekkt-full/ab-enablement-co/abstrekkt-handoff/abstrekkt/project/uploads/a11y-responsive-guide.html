Accessibility & Responsive Design — Reference Guide

The core principle
Use native HTML first, ARIA only when HTML can't do it
A <button> is keyboard-focusable, activates on Enter/Space, and has an implicit role. A <div onclick> needs role="button", tabindex="0", and a keydown handler just to reach the same state. Every ARIA attribute is a maintenance liability — native HTML is free.
HTML5 Landmarks — the skeleton screen readers navigate
Use these elements
<header> site header, one per page
<nav> navigation, label each one
<main> primary content, one per page
<aside> secondary content
<footer> site or section footer
<section> with aria-label or aria-labelledby
Multiple navs need labels
If you have more than one <nav>, distinguish them:

<nav aria-label="Main">
<nav aria-label="Steps">

Without labels, screen reader users hear "navigation, navigation" with no way to differentiate.
ARIA roles, properties, states — the critical ones
Tab widget pattern
<div role="tablist" aria-label="Sections"> <button role="tab" id="tab-1" aria-selected="true" aria-controls="panel-1"> Section 1 </button> </div> <div role="tabpanel" id="panel-1" aria-labelledby="tab-1" tabindex="0"> Content... </div>
Toggle / switch pattern
<!-- Native checkbox --> <input type="checkbox" id="dark-mode" checked /> <label for="dark-mode">Dark mode</label> <!-- Custom switch (ARIA) --> <div role="switch" aria-checked="true" tabindex="0" aria-label="Dark mode" onKeyDown="handleSpace"> ... </div>
Progress / loading
<!-- Determinate progress --> <div role="progressbar" aria-valuenow="3" aria-valuemin="1" aria-valuemax="10" aria-label="Step 3 of 10"> <div style="width:30%"></div> </div> <!-- Loading state --> <div aria-busy="true" aria-live="polite"> Loading... </div>
Live regions — announcements
<!-- Polite: waits for user to finish --> <div aria-live="polite" aria-atomic="true"> Step 3 of 10: Branching </div> <!-- Assertive: interrupts (use sparingly) --> <div aria-live="assertive"> Error: API unreachable </div> <!-- Off-screen, just for announcements --> <div class="sr-only" aria-live="polite"></div>
Icon-only buttons
<!-- Wrong: no accessible name --> <button> <i class="ti ti-x"></i> </button> <!-- Right: aria-label --> <button aria-label="Close dialog"> <i class="ti ti-x" aria-hidden="true"></i> </button> <!-- Also right: visually hidden text --> <button> <i class="ti ti-x" aria-hidden="true"></i> <span class="sr-only">Close</span> </button>
Decorative vs. informative images
<!-- Decorative: aria-hidden --> <i class="ti ti-settings" aria-hidden="true"></i> <!-- Informative: needs label --> <img src="chart.png" alt="Revenue grew 40% from Q1 to Q2 2025" /> <!-- Complex diagram --> <figure role="img" aria-label="Network diagram: ..."> ...SVG content... </figure>
ARIA states — the most common ones
aria-selected
true/false — tab is active
aria-checked
true/false/mixed — checkbox or switch
aria-expanded
true/false — accordion or dropdown open
aria-current
page/step/true — current item in a set
aria-disabled
true — visually disabled but still in tab order
aria-hidden
true — hides from AT, keeps in DOM
aria-busy
true — region is still loading
aria-invalid
true — form field has a validation error
The non-negotiables
Every interactive element must be reachable
Tab reaches every button, link, form field, and custom control. Escape closes modals and dropdowns. Enter and Space activate buttons. Arrow keys navigate within a component (tabs, radio groups, menus).
Never suppress the focus ring
outline: none on :focus destroys keyboard navigation for sighted keyboard users. Use :focus-visible instead — it shows the ring for keyboard users only, not on mouse click.
Focus styles — the right way
/* Wrong — breaks keyboard navigation */ *:focus { outline: none; } button:focus { outline: none; } /* Right — visible for keyboard, hidden for mouse */ *:focus-visible { outline: 2px solid #60a5fa; outline-offset: 2px; } /* Also fine — custom ring */ button:focus-visible { box-shadow: 0 0 0 3px rgba(96, 165, 250, 0.5); outline: none; }
Keyboard patterns by component
Tab widget
Tab → focus the tablist ←/→ → switch between tabs (and move focus to panel) Home → first tab End → last tab Tab → from tab into panel Shift+Tab → from panel back to tab
Custom switch / toggle
Tab → focus the switch Enter → toggle Space → toggle // In JS: el.addEventListener('keydown', e => { if (e.key === 'Enter' || e.key === ' ') { e.preventDefault(); toggle(); } });
Modal dialog
Opening: Focus first focusable element Trap Tab/Shift+Tab inside modal Set aria-modal="true" Escape → close modal Restore focus to trigger element // Trap example: const focusable = modal.querySelectorAll( 'button, a, input, [tabindex="0"]' ); // cycle focus between first + last
Skip navigation link
/* Always the first focusable element */ <a href="#main" class="skip-link"> Skip to main content </a> /* CSS — visible only on focus */ .skip-link { position: absolute; top: -100%; left: 0; } .skip-link:focus { top: 0; }
Focus management — when to move focus programmatically
Move focus when: a dialog opens (→ first interactive element), a dialog closes (→ trigger button), a page/route changes (→ h1 or main), a step advances in a multi-step flow (→ new content heading).

Don't move focus: on every state change — only when the user's context has actually shifted. Moving focus constantly is disorienting.

Make non-focusable elements focusable for focus management: Add tabindex="-1" to a heading or panel. This makes it receivable via el.focus() but not in the natural tab order.

WCAG contrast ratios
AA — minimum required
4.5:1 — normal text (below 18pt / 14pt bold)

3:1 — large text (18pt+ / 14pt+ bold) and UI components (button borders, input borders, icons with meaning)
AAA — enhanced
7:1 — normal text
4.5:1 — large text

Target AA as your minimum. AAA is aspirational for body copy in important contexts (legal text, medical instructions, error messages).

Forced colors / Windows High Contrast
Don't rely on background-color alone to show interactive states in forced-color mode — borders and text color are what Windows High Contrast mode respects. Always pair background changes with a border or text color change on focus and active states.
Breakpoints
Mobile S320px–479pxSingle column, stacked everything. Minimum viable layout.
Mobile L480px–767pxStill single column. Wider gutters. Sidebar hidden or collapsed.
Tablet768px–1023pxTwo columns possible. Sidebar can appear as horizontal scroll strip.
Desktop1024px–1279pxFull layout. Sidebars, panels, multi-column grids.
Wide1280px+Max-width container centered. No more widening.
Mobile-first CSS — write for small screens first
/* Base styles — mobile first */ .sidebar { display: none; /* hidden on mobile */ } .content { width: 100%; padding: 16px; } /* Add complexity at wider viewports */ @media (min-width: 768px) { .layout { display: grid; grid-template-columns: 200px 1fr; } .sidebar { display: block; /* shown at tablet+ */ } .content { padding: 24px; } }
Touch targets — minimum 44×44px (WCAG 2.5.5)
Too small
button { padding: 4px 8px; font-size: 11px; } /* Rendered size: ~22px tall */ /* Fails on touchscreens */
Correct
button { min-height: 44px; min-width: 44px; padding: 8px 16px; } /* Or extend tap area invisibly */ button::after { content: ''; position: absolute; inset: -8px; }
Fluid typography — scales with viewport
/* Fixed — jumps at breakpoints */ h1 { font-size: 24px; } @media (min-width: 768px) { h1 { font-size: 32px; } } /* Fluid — scales smoothly between 375px–1280px */ h1 { font-size: clamp(20px, 4vw, 32px); } /* Body text — readable on all screens */ body { font-size: clamp(14px, 1.5vw, 16px); line-height: 1.6; }
Horizontal overflow — the most common mobile bug
Causes overflow
/* min-width: auto by default */ .grid { display: grid; grid-template-columns: 1fr 1fr; } /* Children with wide min-content push past the viewport */
Fixed with minmax(0, 1fr)
/* Clamps column to available space */ .grid { display: grid; grid-template-columns: minmax(0, 1fr) minmax(0, 1fr); } /* Also: add to your global reset */ *, *::before, *::after { box-sizing: border-box; } img, video { max-width: 100%; }
Sidebar pattern for this project
/* Default: two-column layout */ #shell { display: grid; grid-template-columns: 172px 1fr; } /* Mobile: sidebar becomes horizontal strip */ @media (max-width: 767px) { #shell { grid-template-columns: 1fr; /* stack vertically */ } #sl { display: flex; flex-wrap: wrap; gap: 4px; border-right: none; border-bottom: 0.5px solid var(--color-border-tertiary); overflow-x: auto; /* allow scrolling if many steps */ } .sb2 { border-left: none; border-bottom: 2px solid transparent; white-space: nowrap; min-height: 44px; /* touch target */ } .sb2.on { border-bottom-color: currentColor; } }
The viewport meta tag — required
<!-- Always include this in <head> --> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <!-- What it does: width=device-width → layout width = device pixels initial-scale=1.0 → no zoom on load Without it, mobile browsers zoom out to fit a 980px desktop layout, making everything tiny. -->
