Personal OS: What I Actually Built

An infographic shows a clean 8-feature dashboard built with Claude Code. Here's what my version looks like — including the parts that are broken right now.

A post went around this month showing a custom personal operating system built with Claude Code. Eight dashboard features: Task CRM, Finance Pulse, Habit Tracker, Nutrition, Calendar, AI Second Brain, Journal, Task Blockers. Supabase for cloud memory. Telegram for voice control. Vercel for deployment. Three monitors. Clean screenshots.

It's a good build. The architecture is sound — Supabase as the persistence layer, Claude Code as the builder, Vercel for hosting. The Telegram voice pipeline (voice prompt → BotFather → Whisper → Supabase → app) is clever. The "data stored in cloud, not tied to any app" philosophy is correct and hard-won.

I have a comparable system. Different tools, different architecture, same ambition. Here's the honest comparison — including the parts that are currently broken.

What's Working

Skills as the operating layer. 50 skills in my Claude ecosystem handle everything from KB article generation to adversarial review to social post drafting. Each skill encodes a specific workflow with fail conditions and gotchas — not just instructions. This is the part that compounds. Every week, the skill library gets slightly smarter because every mistake gets captured as a new gotcha entry.

Base44 as lightweight app builder. 41 apps audited, but the lesson is brutal: entity count is a garbage proxy for quality. My most complex app (Fusion AI, 101 entities) has zero real data. My simplest useful app (TeamSync, 3 entities) has actual simulations from March. The apps that work are the ones that solve a specific problem simply. The apps that don't work are the ones I over-architected.

n8n as the orchestration spine. Workflow automation lives in n8n, not in the apps themselves. Portfolio Command Center, drive automation, webhook triggers. When something needs to happen on a schedule or in response to an event, n8n handles it. This separation — apps for UI, n8n for automation — keeps both layers cleaner.

What's Broken Right Now

Currently down
Supabase bill overdue. The core database layer for Continuum (my most ambitious project — Next.js 16, Supabase, Tailwind 4) is blocked. Last good production deploy was March 23. The Vercel GitHub App connection is also broken and needs manual reconnect. This means I can't deploy new builds or use any Supabase-dependent features across any project until the bill is resolved.

Nobody puts this in their infographic. The reality of a personal OS is that it has the same failure modes as any production system: unpaid bills, broken integrations, stale connections, and the entropy that accumulates when you build faster than you maintain.

The infographic shows the destination. It doesn't show the maintenance schedule — because maintenance isn't photogenic.

What I'd Do Differently

Fewer apps, deeper data. 41 Base44 apps is too many. I'd have been better off with 5 apps that each had rich, real data than 41 apps where most are empty shells with impressive entity schemas. The lesson: the schema is the easy part. Getting real data flowing through it consistently is the hard part.

Supabase as one of multiple persistence layers, not the only one. When Supabase goes down (or the bill lapses), everything that depends on it stops. Base44 runs independently. n8n has its own storage. The projects that survived the Supabase outage are the ones that don't depend on it. The monolith database philosophy ("all data in one cloud") is architecturally clean and operationally fragile.

Maintenance budget built into every build. Every new app, skill, or workflow I build adds maintenance cost. I didn't track that cost. Now I have 50 skills, 25 Vercel projects, and a Supabase bill I forgot to pay. A personal OS needs a personal SLA — even if it's just "check the bill on the 1st."

The Honest Version

The infographic says: "Like having an app designed specifically for you that you can edit at any time." That's true. It's also true that an app designed specifically for you needs a maintainer — specifically you. And "you" has a day job, a daughter, a memoir to write, and a consultancy to launch.

The personal OS is real. It works. Parts of it are down right now and I haven't fixed them yet. That's the version nobody posts.
