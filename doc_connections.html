Patterns, risks, and gaps across the series

⚠️ Missing Citation: The 6× Stanford Stat

Appears as a hard claim in 7 of 10 docs. No paper title, no methodology, no link. If these are going to clients or public channels, this is your weakest link. Either find the source and add it, or hedge to "up to 6x in documented benchmarks."

⚠️ Security Gap in Connector Series

Five Connector docs make no meaningful mention of data security, tenant isolation, or auth beyond "OAuth 2.1 for scalability." For Intinc MSP clients, these docs as written could raise red flags. The Harness series (prompt injection, AgentSpec, 90% unsafe execution prevention) has the material — it just hasn't been ported over.

💡 Strongest Unique Insight: "Harness as Subtractive Engineering"

The Sonnet 4.5 → Opus 4.5 "context anxiety" example is the most concrete, proprietary-feeling insight in the series. It grounds the abstract thesis in something verifiable. It appears in 3 Harness docs but zero Connector docs. Worth elevating into a standalone piece or a bridge article.

💡 Audience Ladder Is Well-Structured

You've covered: Student → General Pro → Ops Manager → Business Leader → Enterprise IT → Principal Architect → Exec/Thought Leader. That's a full funnel. What's missing is a practitioner/developer doc — someone building the harness day-to-day (think Staff Engineer or Senior Dev audience). The Technical Strategy Paper comes closest but is still written for an evaluator, not a builder.

⚠️ "Meta-Harness" (Self-Rewriting) Only In Harness Series

The Stanford meta-harness concept — where a model rewrites its own harness from raw execution traces — is arguably the most forward-looking idea in the series. It has no equivalent in any Connector doc. For a "2026 productivity" framing, this is an omission that dates the Connector docs faster than the Harness ones.

💡 Two Docs Are Structurally Identical Across Different Audiences

Student's Guide and Beyond the Chatbox follow the exact same structure: intro problem → comparison table → 4 integrations → 4-step checklist → forward-looking close. This is either deliberate (content templating) or parallel drift. If deliberate, name the template and use it consistently across all Connector docs.
