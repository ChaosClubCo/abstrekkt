# Capstone Rubric (30% of course)

Scored out of 100. 70 to pass the final gate.

## Dimensions

### 1. Works — 30 pts
| Pts | Criteria |
|---|---|
| 30 | Deployed, live, all claimed features work for a fresh user on another device |
| 20 | Deployed and mostly works; minor feature broken |
| 10 | Runs locally but not deployed, OR deployed but broken |
| 0 | Doesn't run |

### 2. Ownership — 30 pts
| Pts | Criteria |
|---|---|
| 30 | Explains every file and any AI-assisted code accurately |
| 20 | Explains most; one area fuzzy |
| 10 | Can explain only the parts they hand-wrote |
| 0 | Cannot explain their own app (vibe-coder outcome — does not pass) |

### 3. Defense — 20 pts
| Pts | Criteria |
|---|---|
| 20 | Answers "why this approach?" and "what breaks if X?" with real reasoning |
| 12 | Answers most; struggles under follow-up |
| 6 | Surface answers only |
| 0 | Cannot defend decisions |

### 4. Process — 20 pts
| Pts | Criteria |
|---|---|
| 20 | Incremental commit history, spec written first, no secrets in repo, clean README |
| 12 | Good history, minor hygiene gaps |
| 6 | One big commit / weak spec / minor secret-hygiene issue |
| 0 | Secrets committed OR no meaningful history |

## Hard rules
- **Any real secret found committed = automatic 0 on Process** + mandatory remediation walkthrough (rotate + gitignore). This mirrors the course's non-negotiable security rule.
- **Ownership < 10 = does not pass**, regardless of other scores. An app the student can't explain fails the entire purpose of the course, no matter how impressive it looks.

## Pass = 70+ AND Ownership ≥ 20 AND deployed.
This guarantees every passing student has shipped a real app they can explain and defend —
which is precisely the FSR bar.
