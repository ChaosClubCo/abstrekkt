# Week 4 — Your First Repo (End to End) 🐣→🚶

**Phase:** Crawl (gate week) · **Survey gap:** Git (1.8) + writing code (1.7)
**Goal:** Run the full real-world loop once, start to finish, so the whole workflow clicks.

## TL;DR
This week you put Weeks 1–3 together: make a small real thing, track it in Git, push it to GitHub, and open a **pull request** — the exact motion used on every software team on earth.

## Analogy
A **pull request (PR)** is a **"please review my change before it goes in" note**. On a real team you don't just shove code into `main`; you propose it on a branch and someone (or you) reviews and approves. It's a quality gate. You'll live in PRs for the rest of your career.

## What you'll build
A tiny personal profile page — plain HTML. No frameworks, no AI yet. The point isn't the code; it's proving you can drive the *workflow* without help.

## The full loop (memorize this shape)
```
clone/init → branch → edit → add → commit → push → open PR → review → merge
```
Everything in Phase 2 and 3 is a bigger version of this exact loop.

## Why "no AI yet"
You're one week from being allowed to pair with AI (Week 7). Before that, you do the loop *manually once* so that when the AI speeds it up later, you can tell whether it did the right thing. That's the "direct and verify" mindset from Day 1.

## Technical definition
A **pull request** is a request to merge one branch's commits into another, providing a diff, a place for review comments, and a merge gate. It is the standard unit of collaboration on Git hosts.
