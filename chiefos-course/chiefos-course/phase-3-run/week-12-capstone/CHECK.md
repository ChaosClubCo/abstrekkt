# Week 12 — Check & Submit (FINAL GATE — 30%)

## Gate criteria
- [ ] App is deployed and live at a public URL.
- [ ] Repo is clean (no secrets), with a commit history showing real, incremental work.
- [ ] `DEFENSE.md` explains every file and the design decisions.
- [ ] Student delivers the 5-minute demo and answers defense questions.

## Submit
1. Live URL.
2. Repo URL.
3. `capstone-spec.md` + `DEFENSE.md`.
4. Deliver the live demo (or recorded, per instructor).

## Grading (see rubrics/capstone-rubric.md for the full scored version)
| Dimension | Weight |
|---|---|
| Works (deployed, does what it claims) | 30% |
| Ownership (can explain every part) | 30% |
| Defense (answers "why" and "what if") | 20% |
| Process (commits, spec, security hygiene) | 20% |

## Instructor grading note (final gate)
- The defense Q&A is decisive. Open a random file and ask them to explain it. Ask "what breaks if the database is down?" A student who ships a working app but folds under "explain this function" has not met the bar — that's the vibe-coder outcome this whole course was built to prevent.
- Honest AI use is fine and expected. Inability to explain AI's output is not.

## FSR pipeline note
Strong capstones + strong defenses are the FSR interview shortlist. What you just did — spec,
build, deploy, defend under questioning — IS the Field Service Rep job. You didn't take a
coding class. You proved you can ship and stand behind software.
