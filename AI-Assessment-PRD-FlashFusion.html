AI Assessment App v3.1.0

Product Requirements Document — INT Inc.

Version 1.0 Jan 20, 2026 Engineering · Design · QA

Executive Summary

The INT Inc. AI Assessment App v3.1.0 is a strategic enterprise application designed to centralize, standardize, and manage the implications and compliance of Artificial Intelligence (AI) initiatives across INT Inc. departments — Operations, Finance & Accounting, HR, and Legal/Compliance. It empowers stakeholders to conduct thorough assessments, mitigate risks, ensure regulatory adherence, and foster responsible AI adoption. The app improves decision-making, enhances operational efficiency, and provides a clear view of the organization's AI landscape by consolidating AI-related data and processes into a single source of truth.

Problem Statement & User Impact

The Challenge

INT Inc.'s increasing AI integration presents challenges in consistently assessing, managing, and ensuring compliance across departments due to fragmented, manual, and siloed processes.

  • Inconsistent Assessments: Varied quality and incomplete data due to lack of a unified framework.
  • Compliance Gaps: Difficulty tracking AI regulations and internal policies, increasing non-compliance and reputational risk.
  • Operational Inefficiencies: Significant manual effort for data collection, analysis, and reporting.
  • Lack of Centralized Visibility: Stakeholders lack a comprehensive, real-time view of AI initiatives, hindering strategic planning.

User Impact

  • Operations Managers: Struggle with understanding AI efficiency, resource implications, and assessment progress.
  • Finance & Accounting Teams: Lack visibility into AI project costs, ROI, and financial risks.
  • HR Professionals: Challenged to assess AI's impact on workforce planning, job roles, training, and ethics.
  • Legal & Compliance Officers: Face difficulties defining, monitoring, and enforcing AI governance and data privacy.
  • Senior Leadership: Lacks a holistic dashboard for AI maturity, risk exposure, and strategic alignment.

User Stories & Acceptance Criteria

User Story Acceptance Criteria
AI Project Lead — Submit new AI project for assessment.
  • Initiate new project assessment form.
  • Form includes project name, description, module ownership, initial scope.
  • Project marked "Pending Assessment" upon submission.
  • Relevant module owners notified.
Operations Manager — View AI project status under my domain.
  • Dashboard shows AI projects owned by/relevant to Operations.
  • Project displays current assessment status (Pending, In Progress, Completed, Flagged).
  • Filter projects by status, due date, assigned assessor.
Legal/Compliance Officer — Define and apply compliance rules to AI projects.
  • Create, edit, archive compliance rules (name, description, severity, modules).
  • Link rules to assessment questions or project types.
  • System flags non-compliant answers or project attributes.
HR Specialist — Access assessments related to AI's workforce impact.
  • View specific assessment sections on HR impact (job displacement, skill gaps, training).
  • Filter HR findings by project and department.
  • Generate summary reports on workforce impact.
Finance Controller — Review financial implications of AI projects.
  • View project budget vs. actuals (if integrated).
  • See financial assessment results (cost savings, ROI projections).
  • Export financial data for AI projects.
Assessor — Complete assigned assessment questionnaires.
  • View list of assigned assessments.
  • Access and fill out dynamic questionnaires (text, number, multiple choice).
  • Save progress and submit completed assessment.
  • Input validation prevents incomplete form submission.
System Administrator — Manage user roles and permissions.
  • Add, edit, deactivate user accounts.
  • Assign predefined roles (Project Lead, Assessor, Admin, Viewer).
  • RBAC enforced across the application.
Authorized User — View audit trail of changes.
  • Access log showing who made what changes, to which entity, and when.
  • Audit logs are immutable with timestamps and user identifiers.
  • Audit trail is searchable and filterable.

Technical Requirements

Frontend

React-first, TypeScript throughout, zero runtime type surprises:

  • Next.js (App Router) — SSR/SSG + API Routes
  • TypeScript — Strict mode, end-to-end typing
  • React — Component layer, hooks-based state
  • Recharts — Data visualization for dashboards and reports

Backend & Infrastructure

Serverless-first with enforced RLS at the data layer:

  • Supabase — PostgreSQL, Auth, pgvector, RLS, Realtime, Storage
  • Upstash Redis — Session caching, rate limiting, job queues
  • Vercel — Deployment, serverless functions, edge middleware
  • Cloudflare Workers — AI proxy layer; keeps provider keys server-side

AI Layer

Claude as the silent OS; Gemini as fallback; all calls proxied through Cloudflare:

  • Claude (Anthropic) — Primary LLM for assessment assist, summarization, compliance flagging
  • Gemini — Fallback provider; cost-optimized for high-volume batch tasks
  • pgvector (Supabase) — Semantic search over assessment history and compliance rules

Observability & Ops

Full-stack visibility from user event to LLM trace:

  • PostHog — Product analytics, feature flags, session replay
  • LangSmith — LLM call tracing, prompt versioning, eval pipelines
  • Stripe — Billing hooks if external licensing is introduced post-V1
  • n8n — Notification workflows, assessment reminders, webhook automations

Proposed API Endpoints

RESTful, served via Next.js API Routes. Authentication via Supabase Auth + Next.js middleware.

POST /api/auth/login
  Request:  { email: string, password: string }
  Response: { access_token, refresh_token, user }

GET  /api/projects
  Params:   status, module_id, search
  Response: [{ id, name, description, status, ... }]

POST /api/projects
  Request:  { name, description, module_owner_id, ... }
  Response: { id, ... }

PUT  /api/assessments/[id]/answer
  Request:  { question_id, answer_value }
  Response: { message: "Answer saved" }

GET  /api/compliance/rules
  Response: [{ id, name, description, severity, ... }]

GET  /api/reports/summary
  Response: { ...summary_data }

assessment_templates id (PK), name, description, target_module_id (FK)
assessment_questions id (PK), section_id (FK), question_text, question_type, options (JSONB)
question_answers    id (PK), assessment_id (FK), question_id (FK), answer_value, answered_by (FK)
compliance_rules    id (PK), name, description, severity, module_id (FK), enforcement_logic (JSONB)

audit_logs          id (PK), user_id (FK), action, entity_type, entity_id, old_value (JSONB), new_value (JSONB), timestamp

  • Automated daily database backups

Usability & Accessibility

Maintainability

Dependencies & Risks

Dependencies

  • Internal Stakeholder Engagement — Timely input from Legal/Compliance, HR, Finance, Operations.
  • Supabase Stability & Features — Reliance on Supabase backend services.
  • Vercel Platform — Dependence on Vercel infrastructure.
  • Security Review & Compliance Team — Clear internal security policies and external regulatory guidelines.
  • Design & UX Team — Availability for designs and flows.
  • IT Infrastructure — Cooperation for network configurations or integrations.

Risks & Mitigation

  • Scope Creep: Strict adherence to "Out of Scope," clear prioritization.
  • Data Migration Complexity: Dedicated migration strategy, thorough testing.
  • Security Vulnerabilities: Secure coding practices, regular reviews, external penetration testing.
  • Performance Bottlenecks: Proactive performance testing, query optimization, Supabase scaling.
  • Integration Challenges: Loose coupling design, well-defined APIs, early research.
  • User Adoption: User involvement in design, comprehensive training, iterative feedback.

Out of Scope

To maintain focus for V1, the following features are explicitly out of scope:

  • Direct AI model performance evaluation.
  • Integration with external AI/MLOps platforms.
  • Advanced NLP/Generative AI features within the app itself.
  • Full multi-tenancy for external clients.
  • Mobile native applications (iOS/Android).
  • Direct real-time integration with INT Inc.'s core ERP/accounting systems.
  • Advanced workflow automation engines.

Security Considerations

Leveraging Next.js, Supabase, and Vercel — adherence to OWASP Top 10 is a hard requirement, not a guideline:

  • A01 Broken Access Control: Strict RBAC via Supabase RLS.
  • A02 Cryptographic Failures: TLS 1.2+, Supabase encryption at rest.
  • A03 Injection: Parameterized queries, input sanitization.
  • A04 Insecure Design: "Secure by design" approach, threat modeling.
  • A05 Security Misconfiguration: Proper RLS, secure deployment config.
  • A06 Vulnerable Components: Regular dependency updates, Snyk scanning.
  • A07 Authentication Failures: Full Supabase Auth, robust session management.
  • A08 Data Integrity Failures: Input validation, database constraints.
  • A09 Logging & Monitoring: Comprehensive event logging and monitoring solutions.
  • A10 SSRF: Rigorous URL validation for all external requests.
