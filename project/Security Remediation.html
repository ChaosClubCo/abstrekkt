00

Before anything: rotate

If a real key was ever pasted into the Figma Make chat or set in a deployed build, treat it as exposed and rotate it now — Anthropic, OpenAI, GitHub, Stripe, and the Supabase service-role key. The fixes below stop future leaks; rotation closes the past ones.

01

The rule that prevents most leaks

Non-negotiable

NEXT_PUBLIC_* and VITE_* variables are compiled into the browser bundle. They are public. Never give a secret one of those prefixes.

Secrets live only on the server and are reached through a backend proxy. The anon key, publishable Stripe key, and analytics IDs are public by design — those are fine to expose.

02

Fix 1 · Stop the browser env leak (File 03)

The old lib/env.ts surfaced LLM keys, a GitHub token, and the Supabase service-role key to the client. The new one exposes public values only and throws if any secret name is read in the browser.

Before — secrets in client config

VITE_ANTHROPIC_API_KEY: safeGetEnvVar('VITE_ANTHROPIC_API_KEY'),
VITE_GITHUB_TOKEN:      safeGetEnvVar('VITE_GITHUB_TOKEN'),
SUPABASE_SERVICE_ROLE_KEY: safeGetEnvVar('SUPABASE_SERVICE_ROLE_KEY'),
// …all inlined into the bundle

After — guarded, public-only

export const ENV = new Proxy(publicEnv, {
  get(t, prop) {
    if (FORBIDDEN_IN_BROWSER.includes(prop))
      throw new Error(`"${prop}" is server-only`);
    return t[prop];
  },
});
03

Fix 2 · Move the key behind a proxy (File 02)

The enterprise app instantiated the Anthropic SDK in the browser with the API key. The replacement client holds no key — it calls your backend with the user's auth token.

Before — SDK + key in the app

this.client = new Anthropic({
  apiKey: process.env.ANTHROPIC_API_KEY
});
// bundled → key visible to every visitor

After — token'd call to proxy

await fetch(`${ENV.API_BASE_URL}/chat`, {
  method: 'POST',
  headers: { Authorization: `Bearer ${token}` },
  body: JSON.stringify({ prompt, ...options }),
});
// key never leaves the server
04

Fix 3 · Authenticate & lock the proxy (File 02)

The proxy accepted any origin and trusted a spoofable x-user-id header. Now it verifies a real Supabase token, derives the user from it, and only answers known origins.

Before — open & spoofable

cors({ origin: "*" })
const userId =
  c.req.header("x-user-id") || "anonymous";
// anyone can call it & reset limits

After — allowlist + verified user

cors({ origin: o => ALLOWED_ORIGINS.includes(o) ? o : "" })
const { data } = await supabase.auth.getUser(token);
const userId = data.user.id; // trusted

06

Apply it

  1. Rotate every credential that may have been used in a build or chat.
  2. Copy the drop-in files over their originals (paths mirror each repo).
  3. Add .gitignore; remove any committed .env from git history.
  4. Move secrets into your host's encrypted env UI — never a committed file.
  5. Set ALLOWED_ORIGINS on the Supabase function to your real domains.
  6. Point all client LLM calls at the proxy (askClaude / streamClaude).
  7. Keep the gitleaks CI check (File 03 has one) on every PR.
  8. Verify in DevTools → Sources that no sk-, ghp_, or service-role string is in the shipped bundle.
