What this board is

The Source Map is a flat, non-hierarchical knowledge graph of the memoir Construction, Not Recovery by Kyle Rosebrook. It maps the book's working system — thesis, evidence, characters, source documents, narrative threads, contradictions, and drafting workflow — as an interconnected network.

It is deliberately not a tree. No node is the root. The thesis doesn't sit "above" the evidence; the letter doesn't "contain" the characters. Every connection is an argument with a stated reason, and the reasons are the point: the board exists so the relationships stay inspectable.

DESIGN PRINCIPLE

This is an evidence board for a literary memoir, not a corporate strategy map. Node labels stay concise; relationship explanations stay detailed. If a thread can't state why two things connect, it doesn't belong on the board.

Threads

  • Primary threads (brighter) carry the eleven relationships the book is structurally built on.
  • Evidence-backed threads light blueprint blue when selected — connections underwritten by clinical or archival documents rather than recollection.
  • Machine-filed threads (dashed) were proposed by the intake layer and approved by you; they remain visually distinct from hand-placed threads.

Every node carries a TAG (e.g. EVD·02) — category prefix plus index — used in tooltips, the side panel, and this documentation to reference entries unambiguously.

03

Filing a source

The intake flow adds new material to the board — a journal, a scan, a worksheet, a note — without letting anything land silently.

  1. Pick. Upload or drop a file (text formats are read directly, up to 6,000 characters; binaries are filed by name + your note), or type a note describing the document.
  2. Analyze. If the machine layer is available, it reads the material and drafts a proposal: label, category, blurb, and proposed connections with reasons. If not, you're routed to manual filing with the same form.
  3. Review. The proposal is fully editable — relabel, recategorize, rewrite the blurb, toggle individual connections on or off, rewrite any reason.
  4. Commit. Only on Commit to board does the node land. Machine-proposed threads stay dashed so their provenance remains visible.
APPROVAL GATE

The machine layer never writes to the board directly. Every AI-proposed node and thread passes through your review, and rejected proposals leave no trace. See §05 for what the model is told.

Session scope: committed additions live in the browser session. To make an entry permanent, add it to the seed data (§04) — the review step shows the exact fields you need.

04

Data schema

All permanent data lives in abstrekkt/memoir-graph.jsx as two arrays: SEED_NODES and SEED_EDGES.

Node

FieldTypeMeaning
idstringStable key, lowercase, no spaces. Referenced by edges — never rename without updating both.
tagstringDisplay reference, PFX·NN — THS, SBJ/FRM, EVD, HIS, BLD, CRF prefixes.
catenumthesis · subject · evidence · history · build · craft — drives color and legend.
hubbool?Renders larger with stronger pull. Reserve for thesis-level nodes and the Diagnostic Instinct.
labelstringConcise display name (aim ≤ 4 words; the style rule is short labels, detailed reasons).
blurbstring1–2 sentence panel description. Written in the book's register (§06).

Edge

FieldTypeMeaning
a, bstringNode ids at either end. Flat graph: direction is rhetorical (A kind B), not hierarchical.
kindstringShort verb phrase: depends on, frames, supports, explains, mirrors, compensates for…
reasonstringRequired. The full sentence explaining why the connection exists. This is the board's actual content.
pbool?Primary thread — one of the book's structural relationships. Renders brighter.
evdbool?Evidence-backed — lights blueprint blue on selection.
aibool?Machine-filed — renders dashed. Set automatically by intake; don't hand-set on seed data.

Adding a permanent entry

// 1. Append the node
{ id: "worksheets", tag: "EVD·05", cat: "evidence", label: "Therapy Worksheets",
  blurb: "Structured exercises from ▮▮▮▮ — dated, contemporaneous, unglamorous." },

// 2. Append its edges — every edge needs a reason
{ a: "worksheets", b: "archive", kind: "is part of", evd: true,
  reason: "The worksheets sit inside the Primary Source Archive as dated records." },

Rules of thumb: reuse existing kind verbs before inventing new ones; a node with no edges shouldn't exist; if you can't write the reason, the connection isn't real yet.

05

The machine layer

Intake analysis calls the embedded Claude completion API (window.claude.complete) when the board runs inside a host that provides it. Availability is feature-detected; without it, intake falls back to manual filing with identical capabilities minus the draft proposal.

The model receives: the document text (or filename + your note), the current node list with categories and blurbs, the category definitions, and a strict-JSON contract. It returns a single proposal object — label, category, blurb, and candidate connections each carrying a reason. Malformed responses surface as a visible error state with a retry, never a silent failure.

BOUNDARIES

The machine layer classifies and proposes. It does not commit, delete, or edit existing nodes; it cannot mark its own proposals as primary; its threads stay permanently dashed. Provenance is a first-class visual property.

06

Editorial rules — the Voice System, codified

Everything written on the board (labels, blurbs, reasons) follows the same rules as the book. The board is part of the memoir's apparatus, not marketing for it.

  • This is literary nonfiction. Not a recovery memoir, not self-help, not a productivity manifesto, not an addiction confessional. Copy that drifts into those registers gets rewritten.
  • No recovery clichés, no false epiphany. No "journey," no "rock bottom," no arc that resolves. Construction is ongoing labor, not a before/after.
  • No toxic positivity. Chaos is acknowledged and organized, never erased or reframed as a gift.
  • Uncertainty stays uncertain. Where memory can't be pinned (dependency onset at 19 or 21), the board says so. Contradiction between sources is content, not an error to resolve.
  • Systems are survival infrastructure, not flexes. External cognition is described plainly — what it replaces, what it costs.
  • Evidence is evidence. Clinical findings (SPECT, July 2022; the 99th/12th split) are stated as findings, without dramatization or diagnosis-as-identity.
07

Sensitive-material handling protocol

HARD RULE · KINSLEY

Kinsley is the book's addressee, grounding constraint, and reason for accountability — a person to protect, not a character to develop. On the board she exists only through the Letter to Kinsley frame node. Do not add nodes detailing her life, image, schedule, or words. Intake proposals that would do so are rejected at review.

HARD RULE · MICHAEL RELATIONSHIP JOURNAL

The journal is evidence, never spectacle. Its board presence is limited to existence, date-range, and evidentiary function (anchoring or contradicting recall). Quotations, intimate specifics, and third-party identifying details stay off the board and out of blurbs. It corroborates timelines; it does not perform them.

  • Archive materials (journals, poems, worksheets, personal documents): reference by type and date, not by content excerpt, unless the excerpt already appears in the manuscript.
  • Third parties: real names appear only where the manuscript has settled on using them; otherwise role-names ("the manager at O'Toole's").
  • Redaction is a feature. Use ▮▮▮▮ marks for withheld specifics rather than paraphrasing around them — visible withholding is honest; smooth paraphrase pretends completeness.
  • Clinical material is Kyle's own and appears at the granularity he has chosen (scan date, facility, the split). Don't enrich it with inferred diagnoses.
  • Sharing the board: it references sensitive sources but contains no raw excerpts, so it can be shown to collaborators as-is. The underlying archive files are never attached to this project.

Layout engine — decisions that matter

  • Custom force simulation (repulsion + spring edges + centering), ~340 tick warm-up, then a low-alpha live loop for drag response.
  • Synchronous warm-up in the render body — not inside requestAnimationFrame. Preview iframes throttle rAF when offscreen; the board must lay out regardless of frame scheduling. rAF is polish only.
  • Live state via refs (nodesRef / edgesRef / spreadRef / dimRef) so the sim loop never closes over stale props — the class of bug behind several v1.3 fixes.
  • Measured sizing, single source of truth: a useLayoutEffect ResizeObserver measures the board before first paint; canvas width tracks it exactly (no fixed floor), and compact derives from the same measurement — never from matchMedia.
  • Scroll, don't clip: the canvas keeps a minimum height and the board scrolls on short viewports. Nodes clamp to bounds using their true half-dimensions (positions are center-based).

Maintenance rules

  • Edit seed data freely; ids are the only fragile part (edges reference them).
  • Keep node labels ≤ ~4 words — card width assumes it.
  • Don't reintroduce matchMedia for layout decisions or move the warm-up into rAF (see §09 for why).
  • New categories need: a CAT entry, a CSS custom property (--c-*), and a legend check.
