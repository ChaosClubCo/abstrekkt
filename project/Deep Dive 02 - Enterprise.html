The good bones — and the duplicate skeleton

Feature-folder layout, NavigationContext / ToastContext, reusable Button/Badge/Toast primitives, real hooks. Closest to shippable of the three. Then it forks into itself.

/features, /components, /contexts, /hooksCLEAN
Sensible domain separation; typed; sr-only, :focus-visible, print & reduced-motion-friendly base CSS.
/features ⟂ /src/featuresDUPLICATED
Deployment, Operations and ROI exist as parallel copies in two trees. So do /components/ui ⟂ /src/components/ui, /utils ⟂ /src/utils, and three copies of the type definitions (/types.ts, /types/index.ts, /src/types/index.ts). Drift is already visible between them.
HIGH

Two Claude integration paths, one dangerous

The app ships both a correct server proxy and a risky in-browser client:

  • Correct: supabase/functions/server — a Hono edge function holding the key server-side, proxying to Anthropic.
  • Dangerous: src/lib/api/claude-client.ts instantiates the Anthropic SDK in the app with process.env.ANTHROPIC_API_KEY. In a Vite SPA, anything bundled client-side is public — if this path is ever used in the browser, the key ships to every visitor.

Two implementations of the same capability also means two rate limiters, two pricing tables, two places for behaviour to diverge.

✓ RESOLVED — the in-browser Anthropic client (/src/lib/api/claude-client.ts) is deleted; only the server proxy remains. Live in remediation/clean/enterprise.

02

The security layer is theatre

security/prompt-injection-defense.ts is 616 lines citing "OWASP Top 10 for LLMs (2025)" and "NIST AI RMF," structured into "6 security layers." Underneath the framing, the core does not work.

CRITICAL

The pipeline never calls Claude — it returns a mock

The "execute" step at the heart of the secure pipeline is a stub. Every downstream "output validation / PII redaction" layer therefore inspects placeholder text, not real model output.

SecureLLMPipeline.executeSafely()// TODO: Integrate with actual Claude API
// For now, return mock response
return 'This is a mock response. In production, this would call the Claude API…';

✓ RESOLVED — the mock prompt-injection-defense.* is deleted; Claude now goes through the authenticated server proxy (supabase/functions/server/index.tsx). Live in remediation/clean/enterprise.

HIGH

HITL & monitoring are all TODOs

The "human-in-the-loop" controller never approves anything (getApprovalStatus hardcodes {approved:false}), the security-team notification is // TODO, and the Sentry hook is commented out. The high-risk path submits a review that no one can ever clear.

✓ RESOLVED — the mock HITL/monitoring file is deleted; replaced by the authenticated proxy with real per-user rate limiting.

HIGH

The real client bypasses the pipeline it imports

claude-client.ts uses securePipeline.processRequest() only as an allow/deny gate, then calls the live API separately. So the pipeline's sanitisation, isolation prompt, and output redaction never touch the actual request or response — they are dead code in the live path.

✓ RESOLVED — the bypassing client is gone; the keyless proxy client is now the single Claude path.

MEDIUM

Regex detection: bypassable in, false-positive out

Detection is a list of English-ish regexes (easily evaded by rephrasing). Meanwhile the matchers are catastrophically broad: the "base64" rule flags any 20+ char unspaced string, and the PII "API key" rule is \b[A-Za-z0-9]{32,}\b — which trips on ordinary IDs, hashes, and slugs. High-confidence blocks on innocent input are guaranteed.

HIGH

Open CORS + spoofable identity on the proxy

The Supabase chat proxy sets origin:"*" and gates rate-limiting solely on an x-user-id header the caller supplies. There is no authentication. Anyone who learns the endpoint can spend your Anthropic budget, resetting the limit by changing one header value.

✓ RESOLVED — proxy now uses a CORS allowlist (ALLOWED_ORIGINS) and verifies a Supabase bearer token; the user id comes from auth.getUser, not a header.

MEDIUM

Fabricated provenance

Docblocks assert authorship and history that never happened: @author INT Inc Security Team, @since 2025-12-11, @version 2.0.0. Invented authority makes non-functional code read as battle-tested. This is the most quietly corrosive pattern in the file.

CREDIT

Accessibility baseline (focus rings, screen-reader utilities, print styles), a coherent component system, typed navigation/toast contexts, and a correct server-proxy option. Strip the theatre and the de-duplication problem, and this is a legitimately good foundation.

04

What this file needs

  1. Delete the in-browser Claude client

    Keep only the server proxy. Never let an LLM key near a bundled SPA.

  2. Either make the security pipeline real, or remove it

    A non-functional 616-line "defense" with fabricated provenance is worse than none — it manufactures false confidence. Wire executeSafely to the proxy and finish HITL, or cut it to a small honest input check.

  3. Authenticate the proxy; lock CORS

    Require a real token, derive the user from it (not a client header), and scope origin to your domains.

  4. Collapse the duplicate trees

    One /src. Merge the parallel features, UI, utils, and the three type files into a single source of truth.

  5. Evict the phase-logs

    One README + one architecture doc. Move the rest out of the deliverable.

  6. Settle the name

    FlashFusion, INT Inc., or FF Inc. — one identity, applied everywhere.
