Three Small Habits from This Week

No theory. No setup. Three small moves I made this week that saved me time.

Kyle Rosebrook · 2 min read

Some weeks deserve a 2,000-word essay. Some weeks just have three things worth writing down. This is the second kind. If you're a self-taught builder shipping AI apps, these are the moves I made this week that saved me real time.

Tidbit 01

Grep your production bundle before you ship.

Build locally. Open the production JS files. Search for sk-, pk_live, and eyJh (the JWT prefix). If anything comes back that shouldn't be public, you've found a leak.

Five minutes. Saved me twice this week from shipping a stray test key. Variables prefixed with NEXT_PUBLIC_ ship to every visitor's browser by design the prefix is a label, not a vault.

Time5 min
FrequencyEvery deploy
SavesOne Moltbook
Tidbit 02

Test in Incognito before you call it done.

Every feature gate, every paywall, every "private" link gets one pass through a logged-out browser before merge. If your private bucket is visible in Incognito, your private bucket is public.

I caught two storage misconfigurations this week running the Incognito check. Both would have been embarrassing if a stranger had found them first. Your authenticated browser is lying to you about what's actually accessible.

Time1 min
FrequencyEvery feature
SavesOne leak
Tidbit 03

Keep active projects off cloud-synced folders.

OneDrive, Dropbox, iCloud, they will fight your dev environment. Two-way sync conflicts will eat your day. node_modules uploads forever. Build outputs trigger sync storms. Your git index gets corrupted in interesting ways.

I keep active code in D:\02_Homebase\Cowork, off any sync provider. Boring. Saves hours a week. If you've been losing time to "why did my repo break overnight," check what folder it's in. The answer is usually that one.

TimeOne-time setup
FrequencyEvery project
SavesHours weekly

The boring habits compound. The clever ones don't.
