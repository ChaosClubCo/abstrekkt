Six Prompts That Keep AI From Making Me Dumber

Each one is named for the failure mode it prevents. Copy them, modify them, save the ones that work. The point isn't the prompt — it's the move.

Kyle Rosebrook · 5 min read

The default mode of any AI assistant is helpful, agreeable, and confident. All three are failure modes when you're using the model for serious work. Helpful becomes sycophancy. Agreeable becomes false consensus. Confident becomes hallucination delivered with a smile.

The prompts below are how I push back. None of them is clever. Each one names a specific cognitive failure mode and asks the model to defend against it. Use them when the stakes are real — decisions you can't undo, drafts that will go public, plans that other people will execute.

§ Against agreement
Augmentor 01 Anti-sycophancy

The Adversarial Prompt

Prevents Sycophancy. Three agreements in a row from any model should set off an alarm — this prompt is the alarm.

Prompt 
Argue against this decision. Don't soften it. Don't hedge. Make
the strongest possible case that I am wrong. Surface the
counterexamples I haven't considered. If you genuinely cannot
find a problem, say so explicitly — but try first.
Use when
Before any decision you can't easily reverse — architecture choices, hires, public statements, contractual commitments.
Skip when
You're brainstorming, exploring options, or the question genuinely has no wrong answers. Don't weaponize this prompt against creative work.
Augmentor 02 Pre-mortem

The Failure Mode Prompt

Prevents Optimism bias. Plans fail because you didn't imagine how they'd fail.

Prompt 
It's six months from now and this plan failed. Walk me through
the most likely reasons, in order of probability. For each one,
name the early signal I would have seen if I were looking. Don't
include "the team didn't try hard enough" — that's not useful.
Use when
Before kicking off a project, before a launch, before committing real time or money to a path.
Skip when
You're already mid-execution. This prompt is for planning, not for second-guessing in flight.
§ Against false confidence
Augmentor 03 Verification

The Gap Audit Prompt

Prevents Confident hallucination. Converts smooth-sounding output into a list of unknowns.

Prompt 
For every factual claim in your previous response, label it as:
[VERIFIED] from a source you can name, [INFERRED] from reasoning,
or [GENERATED] from pattern-matching. List anything you assumed
that I didn't tell you. List the questions whose answers would
change your response.
Use when
Anything going public, anything claiming facts about a person or product, anything that will be quoted or cited.
Skip when
Casual conversation, brainstorming, creative drafting where invention is the point.
Augmentor 04 Steelman

The Other Side Prompt

Prevents Frame lock-in. You're inside one frame and don't know it.

Prompt 
Steelman the position I'm dismissing. Make the case a smart,
honest person would make for the side I'm not on. Don't strawman
it. If the steelmanned version surfaces something I should
actually take seriously, say so directly.
Use when
You catch yourself dismissing a take too quickly. When a colleague disagrees and you can't yet articulate why they might be right.
Skip when
The position is genuinely indefensible (e.g., factually false). Steelmanning bad faith arguments dignifies them.
§ Against drift
Augmentor 05 Scope discipline

The Smallest Version Prompt

Prevents Scope creep. The model will happily build the cathedral when you needed the shed.

Prompt 
What is the smallest possible version of this that would still
solve the actual problem? Don't tell me what "good" looks like —
tell me what "minimum viable" looks like, and what I would learn
by shipping it before building anything bigger.
Use when
Mid-build, when you can feel the project getting larger than the problem warranted. Before any "while we're at it…" decision.
Skip when
The project genuinely requires the larger scope (e.g., security, compliance, regulated workflows). Don't minimum-viable a thing that has to be right.
Augmentor 06 Self-check

The Ground Truth Prompt

Prevents Fluent lying. The drift between what's true and what sounds true is where AI-assisted work fails most reliably.

Prompt 
Before you draft anything, list every claim you're about to make
about me, my work, my tools, or my situation. For each one, tell
me: did I say this in our conversation, did I say it in my
project files, or are you inferring it? Do not include any claim
in the draft that you can't trace to one of those sources.
Use when
Drafting any public-facing content about you — bios, pitches, articles, manifestos. The cost of a confident wrong claim about yourself is higher than almost anywhere else.
Skip when
Pure technical work where you're not the subject. The model can't lie about your code the way it can lie about your biography.

The point isn't the prompt — it's the move underneath it. Once you've used a prompt enough times, the prompt becomes a habit, and you stop having to ask the model the question. You just ask it of yourself.
